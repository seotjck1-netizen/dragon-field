# 앞뒤(깊이) — 누가 누구를 가리는가

> 0.70.22 에 **사람이 물건에 가리는 심각한 오류**가 나서 적어 둡니다.
> 같은 실수를 또 하지 않으려면 여기부터 읽으세요.

## 한 줄 규칙

> **발밑(py)이 아래일수록 나중에 그린다. 발밑이 같으면 사람이 위다.**
> 그리고 **낮은 물건은 아예 이 겨루기에 넣지 않는다** — 바닥에 굽는다.

---

## 무슨 일이 있었나 (0.70.21 → 0.70.22)

0.70.21 에 가구를 사람 크기에 맞게 키웠습니다. 키운 그림을 **배우 목록**에
넣었습니다 — 큰 나무가 그러니까 가구도 그러면 되겠다고 본 것입니다.
"뒤로 걸어갈 수 있게" 하려는 뜻이었습니다.

그 한 줄이 세 가지를 한꺼번에 망가뜨렸습니다.

| 증상 | 어디서 |
|---|---|
| 물건 **앞**에 서 있어도 캐릭터가 물건에 가린다 | 어느 방에서나 |
| 위에서 아래로 **점프해서 앞으로 내려와도** 가린다 | 술통·탁자 |
| 침대 **옆**에 서 있어도 캐릭터가 반투명이 된다 | 여관 |
| 침대가 **벽 속으로 들어간다** | 여관 |

## 왜 그랬나 — 원인은 둘

### ① 발밑이 같으면 누가 위인지 정해 두지 않았다

배우(사람·몬스터·큰 그림)는 **발밑 픽셀(py)** 순서로 그립니다.

```js
actors.sort((a, b) => a.py - b.py);   // ← 0.70.21 까지
```

가구의 py 는 **제 칸의 아래 변**입니다. 사람이 **같은 줄**에 서면
사람의 발밑도 그 칸의 아래 변입니다 — **py 가 똑같습니다.**

둘이 같으면 `sort` 는 원래 순서를 지킵니다. 그런데 배우 목록은

```
[사람, NPC, 몬스터, 다른 접속자, 큰 그림들]
```

순서로 만들어집니다 — **큰 그림이 언제나 맨 뒤**입니다.
그래서 같은 줄에 서면 **가구가 무조건 사람 위로** 그려졌습니다.

가구가 62px 로 커진 뒤에는 한 칸(32px) 옆에 서도 그림이 닿으므로,
**옆에 서기만 해도 가렸습니다.** 점프해서 내려와도 마찬가지입니다 —
착지한 칸이 물건과 같은 줄이면 py 가 같아집니다.

### ② 낮은 물건에까지 "가리면 비친다" 를 걸었다

`_hidesPlayer()` 는 원래 **큰 나무**를 위한 것입니다. 나무 뒤로 걸어 들어가면
통째로 사라지지 않게 반쯤 비춰 주는 장치입니다.

침대가 62px(두 칸 높이)이 되자, 침대에서 **한 칸 위**에 선 사람이
그 판정에 걸렸습니다. 침대는 바닥에 놓인 낮은 물건인데
"나무 뒤에 숨은 사람" 취급을 받은 것입니다.

---

## 어떻게 고쳤나

### 낮은 물건은 **바닥 판에 굽는다**

```js
// FieldScene._groundLayer
if (GROWN.has(tile.sprite)) {
  bake.drawSprite(tile.sprite, tx * T + T / 2, ty * T + T, { anchor: 'bottom' });
  continue;
}
```

바닥 판은 사람보다 **먼저** 그려집니다. 그래서 사람이 언제나 위입니다.

> **탁자 뒤에 숨는 사람은 없습니다.** 낮은 물건은 애초에 앞뒤를 따질 것이
> 아닙니다. 따지지 않기로 하면 따지다 틀릴 일도 없습니다.

⚠ 발밑을 칸 아래 변에 맞춰야 합니다(`anchor: 'bottom'`).
좌상단으로 찍으면 커진 몫이 **아래 칸을 덮습니다.**

### 발밑이 같을 때를 정한다

```js
const zOf = (q) => (q.kind === 'prop' ? 0 : 1);
actors.sort((a, b) => (a.py - b.py) || (zOf(a) - zOf(b)));
```

남은 큰 것(나무·집 지붕)에도 같은 문제가 있었습니다.
**같은 줄이면 사람이 위**입니다 — 사람이 안 보이는 것보다
나무가 조금 가려지는 편이 언제나 낫습니다.

### 침대는 **두 칸짜리**로

그림만 키우면 위 칸(벽)을 덮습니다. 침대는 원래 두 칸을 쓰는 물건입니다.

* `~` 머리맡(위 칸) · `;` 발치(아래 칸)
* 세로는 32 를 **안 넘깁니다**(`tools/gen-assets.js` 의 `GROW`)
* 가로만 42 로 넓힙니다 — 침대는 사람보다 넓습니다

## 새 물건을 넣을 때

| 어떤 것인가 | 어디에 넣나 |
|---|---|
| 낮은 것 (가구·잔해·표지판·계단) | `FieldScene` 의 `GROWN` — 바닥 판에 구워진다 |
| 키 큰 것 (나무·집 지붕) | `TALL` — 배우 목록에 들어가 사람과 겨룬다 |
| 두 칸을 쓰는 것 (침대) | 글자 둘로 나눈다. 세로를 키우지 말 것 |
| 글자가 적힌 표지판 (0.70.25) | 굽지 않고 **세운다**(배우 목록). 판을 글자 길이에 맞춰 그려야 하고, 바닥에 구우면 테두리 숲의 나무가 판을 덮는다. 발밑을 반 뼘(+0.5) 뒤로 두어 같은 줄의 나무보다 앞에 보인다 |

**판단 기준 한 가지:** *그 뒤에 사람이 숨을 수 있는가?*
숨을 수 있으면 `TALL`, 아니면 `GROWN` 입니다.

## 몬스터·NPC 는 어떤가 (0.70.23)

0.70.22 의 고침은 **사람만** 보고 만든 것입니다. 0.70.23 에 몬스터와 NPC 를
물건 네 방향에 세우고 픽셀로 재 봤습니다.

| 어디에 | 결과 |
|---|---|
| 물건 **옆·앞** (나무·침대) | 잘 보입니다 — `zOf` 가 몬스터·NPC 에게도 똑같이 걸립니다 |
| 나무 **바로 뒤** | **0픽셀. 몸도 이름표도 통째로 사라졌습니다** |

### 몸이 가리는 것은 그대로 둡니다

나무 뒤로 걸어 들어가면 가리는 것이 **나무의 일**입니다.
몬스터가 지나갈 때마다 숲이 반투명해지면 들판이 온통 어른거립니다.
사람만 비춰 주는 것(`_hidesPlayer`)은 그대로 둡니다 —
놓치면 안 되는 것은 **내가 어디 있는가** 하나뿐입니다.

### 이름표는 **맨 위로** 올립니다

몸은 가려도 **거기 무언가 있다**는 말까지 덮이면 안 됩니다.
몬스터는 싸울 상대입니다. 이름표는 몸이 아니라 **알림**이라,
풍경에 삼켜질 것이 아닙니다.

```js
// FieldScene.render — 배우를 다 그린 뒤에
for (const actor of marks) {
  if (actor.isBoss) this._drawBossMark(renderer, actor);
  this._drawMonsterTag(renderer, state, actor);
  if (actor.alerted) this._drawAlertMark(renderer, actor);
}
```

⚠ **어둠막보다는 아래**입니다. 어두운 방에서 이름표가 어둠을 뚫고 떠 있으면
"보이는 데까지만 보인다" 가 무너집니다 — 횃불 없이 지도를 읽게 됩니다.

## 재는 연장을 먼저 의심하라 (0.70.23)

처음 잰 값은 네 방향 모두 `0픽셀` 이었습니다. "다 가려졌다" 로 읽힐 뻔했습니다.

틀린 것은 **자**였습니다.

```js
const r = box();          // ← 카메라가 아직 앞 지도 자리에 있다
const withMe = shot();    // ← 여기서야 카메라가 제자리를 잡는다
```

카메라는 `render()` 안에서 제자리를 잡습니다. 그리기 **전에** 자리를 재면
**앞 지도의 카메라**로 상자를 잡습니다. 상자가 화면 밖(음수 y)에 걸리고,
밖은 늘 같은 색이니 차이가 `0` 으로 나옵니다 —
가려진 것처럼 보이지만 사실은 **안 잰 것**입니다.

> **0 은 '없다' 와 '못 봤다' 를 구별하지 않습니다.**
> 0 이 나오면 고치기 전에 **재는 자리부터** 찍어 보십시오.

`batch78` 에도 같은 줄이 있었습니다. 지키던 방이 작아 카메라가 안 움직였기에
**우연히** 맞고 있었을 뿐입니다. 함께 고쳤습니다.

## 시험이 지키는 것

`tiletrans` (브라우저 없이 도는 14줄):

* 얹는 타일에 **투명한 자리가 있다** — 없으면 밑바탕이 안 보인다
* 지도가 **제 바닥을 말한다** — 안 말하면 성 안에 잔디가 깔린다
* `under` 가 **있는 그림**을 가리킨다
* 깔리는 바닥에 **구멍이 없다**
* 크게 구운 것은 **`GROWN` 에 들어 있다** — 안 들어 있으면 아래 칸을 덮는다
* 침대는 **세로로 안 커진다** — 커지면 벽에 파묻힌다
* 머리맡 밑에는 **발치가 있다** — 없으면 반쪽 침대가 된다

앞뒤 순서 자체는 게임을 띄워서 픽셀로 잽니다.

* `batch78` — **사람**을 물건 네 방향에 세운다 (0.70.22)
* `batch79` — **몬스터·NPC** 를 같은 잣대로 세운다. 그리고
  나무 **바로 뒤**에 선 몬스터의 **이름표가 살아 있는지** 본다 (0.70.23)
