# 드래곤 필드 — HTML RPG 확장 뼈대

바닐라 JS(ES Modules) + Canvas로 만든 **드래곤퀘스트식 마을·필드 탐험 + 자동 전투** RPG.
빌드 스텝이 없고 외부 라이브러리를 하나도 쓰지 않습니다.

---

## 실행

두 가지 방법이 있습니다.

```bash
# ① 혼자 하기 — 정적 서버면 충분
cd rpg-game
npx serve .                    # 또는  python3 -m http.server 8000

# ② 같이 하기 — 동봉된 게임 서버 (의존성 0개, npm install 불필요)
node server/server.js          # → http://localhost:8787
PORT=9000 node server/server.js
```

②로 띄우면 계정과 세이브가 서버에 저장되고, **같은 네트워크의 다른 기기에서 같은 주소로
접속하면 같은 필드에서 함께 사냥**할 수 있습니다.
`file://` 로 직접 열면 ES Module과 `fetch`가 막히므로 반드시 서버로 실행하세요.

**조작**: 방향키 / WASD 이동(**둘을 같이 누르면 대각선**) · NPC를 **클릭**하거나 마주 보고
`Enter` 로 대화 · `I` 소지품 · 전투 중 `Enter` 스킵 · `Shift` 홀드 시 4배속 ·
HUD의 **🏠 마을로 귀환** 버튼으로 언제든 포이노 복귀

| 대각선은 **√2 배 오래** 걸립니다 | 안 그러면 대각선으로만 다니는 게 41% 빠릅니다 |
| 바라보는 쪽은 **좌우가 이깁니다** | 대각선 그림이 없습니다. 사람은 좌우 뒤집기로 그리므로 그쪽이 자연스럽고, NPC 에게 말 거는 방향도 좌우가 더 자주 맞습니다 |
| **모서리는 못 뚫습니다** | 옆 두 칸 중 하나라도 벽이면 대각선으로 못 갑니다. 안 막으면 벽 모서리를 스치며 지나가고 두 벽 사이 틈으로 빠져나갑니다 |
| 몬스터가 옆에 서 있는 건 **괜찮습니다** | 벽만 막습니다 — 서 있는 놈 하나 때문에 대각선이 죽으면 답답합니다 |
| 같은 축에서 둘이 눌리면 **나중에 누른 쪽** | 손가락을 굴릴 때 걸음이 끊기지 않습니다 |

### 키보드 — 글자를 칠 때는 게임이 손을 뗍니다 (0.53 에서 고침)

운영자 창에 **`1 시즌` 을 칠 수가 없었습니다.** `1` 은 단축칸, 스페이스는 확인이라
게임이 먼저 집어 갔기 때문입니다. `W`·`A`·`S`·`D`(이동), `I`·`C`·`M`·`R`·`O`(창),
엔터·Tab·Esc 도 모두 같은 일을 겪었습니다.

```js
// core/Input.js
function isTyping(e) { …INPUT · TEXTAREA · SELECT · contentEditable… }
_onKeyDown(e) {
  if (isTyping(e)) return;                       // 게임은 아무것도 안 한다
  if (e.isComposing || e.keyCode === 229) return; // 한글 조합 중에도 손대지 않는다
  …
}
```

> **한 글자마다 창을 다시 그리지 않습니다.** 예전에는 글자 칸에 뭔가 칠 때마다
> 창 전체를 새로 만들고 커서를 되돌려 놓았습니다. 영어는 그럭저럭 됐지만
> **한글은 조합이 깨집니다** — 'ㅅ' 을 친 순간 칸이 새로 만들어져 '시' 로 못 이어집니다.
> 이제 확인 글 칸은 **단추의 잠금만** 그 자리에서 풀고, 찾기 칸은
> **조합이 끝난 뒤에만** 다시 그립니다. 접속 화면은 다시 그려도 적던 아이디를 지킵니다.

### 깃허브에 올리기 — `upload.bat` (윈도우, 0.51)

폴더 안의 **`upload.bat` 을 더블클릭**하면 깃허브에 올라가고 Render 가 다시 배포합니다.

- **폴더를 옮겨 다니지 않습니다.** 이 파일이 이미 `rpg-game` 안에 있으므로
  `cd rpg-game` 을 하면 오히려 "폴더를 찾을 수 없습니다" 로 끝납니다.
- 커밋 글의 판 번호는 `package.json` 에서 **읽습니다.** 손으로 적으면 언젠가
  `Update0.44.0` 인 채로 0.51 을 올리게 됩니다.
- `.gitignore` 가 없으면 만들어 둡니다 — **`server/data/`(계정과 비밀번호)를
  절대 올리지 않기 위해서**입니다.

## 휴대폰 · 태블릿에서 하기

터치 기기로 열면 자동으로 알아채고 **화면 아래에 조작 버튼**이 나옵니다
(방향 패드 · 확인 · 취소 · 단축키 1·2 · 소지품 · 캐릭터 · 설정).
방향 패드는 **조이패드처럼** 동작합니다 — 패드 아무 데나 누르면 잡히고, 누른 채 밀면
방향이 따라옵니다. 화살표를 정확히 짚지 않아도 되고, 손가락이 패드 밖으로 미끄러져도
끊기지 않습니다. 한가운데(반지름의 22% 안)는 데드존이라 방향이 잡히지 않습니다.
손을 떼면 멈춥니다.

640×480 화면은 기기 크기에 맞춰 **통째로 축소**됩니다(캔버스만 줄이면 위에 얹힌 UI 와 좌표가 어긋납니다).
세로보다 **가로로 눕히면 훨씬 큽니다** — 세로에서는 안내가 한 번 뜹니다.

### 아이폰 사파리에서 특히 조심할 것

| 문제 | 왜 생기나 | 어떻게 해결했나 |
|---|---|---|
| 로그인 자체가 안 됨 | `crypto.subtle` 은 **https 또는 localhost 에서만** 있습니다. 폰으로 `http://192.168.0.5:8787` 같은 집 안 주소나 저장한 파일(`file://`)을 열면 없습니다. | `src/core/Sha256.js` 에 순수 자바스크립트 SHA-256 을 두고, 없을 때 대신 씁니다. **결과 해시가 같아 기존 계정이 그대로 열립니다.** |
| 화면이 그려지다 멈춤 | `ctx.roundRect()` 는 사파리 **16.4 이상**에만 있습니다. 맵 이름 배너가 이걸 써서, 구버전 iOS 는 맵에 들어서자마자 그리기가 통째로 죽었습니다. | `src/core/Canvas2d.js` 의 `roundRectPath()` 로 감싸 없으면 직접 그립니다. |
| 화면이 잘려 나감 | 640px 판이 폭 390px 짜리 화면에 그대로 들어갑니다. | `src/core/Viewport.js` 가 화면에 맞춰 스테이지를 축소합니다. |
| 움직일 수가 없음 | 키보드가 없습니다. | `src/ui/TouchControls.js` 의 화면 조작 버튼. |
| 단일 파일만 유독 깨짐 | 빌드가 `viewport` 메타 태그를 빠뜨려 사파리가 980px 데스크톱 화면으로 그렸습니다. | `tools/build-single-file.js` 가 `index.html` 의 메타 태그를 그대로 가져갑니다. |
| 개인정보 보호 모드에서 멈춤 | 사파리 프라이빗 모드는 `localStorage` 에 쓰기만 해도 예외를 던집니다. | `core/Storage.js` 가 모든 접근을 감싸고, 저장이 안 되면 안내 문구를 보여 줍니다. |

> **가장 쾌적한 방법** — 서버를 켜고(`node server/server.js`) 폰 사파리에서 `http://<PC의 IP>:8787` 로 들어간 뒤
> **공유 → 홈 화면에 추가**를 누르세요. 주소창 없이 전체 화면으로 돌아가고 세이브도 서버에 남습니다.

## 미리보기 창에서는 열리지 않습니다

메일·메신저·편집기의 **미리보기 창**(페이지 안에 끼워 넣은 틀) 안에서 열면

접속 화면은 멀쩡히 보이는데 **버튼만 아무 반응이 없습니다.**

```
Blocked form submission because the form's frame is sandboxed
and the 'allow-forms' permission is not set.
```

진단이 전부 통과로 나오는데도 시작이 안 된다면 이 경우입니다.
진단의 **여는 방법**이 `about:` 이나 `blob:` 이면 미리보기 창입니다.

- **해결** — 파일을 컴퓨터에 **저장한 뒤** 그 파일을 더블클릭해서 브라우저로 여세요.
- 지금은 이 상황을 감지해 접속 화면 맨 위에 노란 경고를 띄웁니다.
- 버튼도 폼 제출에만 기대지 않고 **클릭과 Enter 로 직접 동작**하도록 바꿔,
  대부분의 미리보기 창에서도 그냥 눌립니다.
- 저장이 아예 막힌 곳에서도 게임은 시작됩니다(진행이 남지 않는다고 알려 줍니다).

## "계정 만들고 시작" 버튼이 안 눌릴 때

접속 화면은 보이는데 버튼만 반응이 없다면 대개 **버튼이 화면 밖으로 밀려나 있던 것**이었습니다.
창 높이가 낮거나 폰을 눕히면 새 계정 폼(아이디·비밀번호·이름·직업 3칸)이 길어져
버튼이 접히는 자리 아래로 내려갔는데, 스크롤해야 한다는 표시가 없었습니다.

지금은 이렇게 바뀌었습니다.

- **버튼은 스크롤 영역 밖에 고정**돼 있어 창이 아무리 낮아도 항상 제자리에 보입니다.
- 낮은 화면에서는 설명글과 제목을 접어 **입력칸에 자리를 양보**합니다.
- 접속 화면이 640×480 게임 판 **밖으로** 나왔습니다. 화면에 맞춰 축소되지 않으니
  글씨가 작아지지도, 카드가 잘리지도 않습니다.

그래도 안 되면 접속 화면 아래 **[진단]** 버튼을 눌러 보세요. 빨간 ✗ 가 원인입니다.

어떤 컴퓨터에서든 똑같고, 이제는 화면이 그 사실과 해결책을 직접 알려 줍니다.

접속 화면 오른쪽 아래에 **버전(v0.9.0)** 이 찍혀 있습니다. 파일을 여러 컴퓨터로 옮겨 다닐 때

그 옆의 **[진단]** 버튼을 누르면 지금 환경을 항목별로 점검해 보여 줍니다.


빨간 ✗ 가 있으면 그게 접속이 안 되는 이유입니다.

## 접속이 안 될 때 (다른 컴퓨터·폰)

**계정은 만든 그 기기의 그 브라우저 안에만 저장됩니다.**
서버 없이 HTML 파일만 열었다면, 컴퓨터에서 만든 아이디는 폰이나 다른 컴퓨터에 존재하지 않습니다.
그 상태에서 접속을 누르면 당연히 "없는 아이디입니다"가 나옵니다 — 고장이 아니라 저장 위치의 문제입니다.

해결책은 두 가지입니다.

### ① 서버를 켠다 (기기끼리 계속 이어서 할 거라면)

```bash
node server/server.js
```

켜면 폰에서 칠 주소를 콘솔이 직접 알려 줍니다.

```
  📱 폰·태블릿에서는 아래 주소를 사파리 주소창에 그대로 치세요
     (같은 와이파이에 연결되어 있어야 합니다)
       http://192.168.0.14:8787
```

이 주소로 들어가면 계정이 **서버에 저장**되어 폰·컴퓨터 어디서든 같은 아이디로 이어집니다.
접속 화면 아래에도 "서버에 저장되므로 다른 기기에서도 이어서 할 수 있습니다"라고 표시됩니다.

안 될 때 확인할 것:

- 폰과 컴퓨터가 **같은 와이파이**인가 (폰이 셀룰러면 안 됩니다)
- 컴퓨터 방화벽이 8787 포트를 막고 있지 않은가 (윈도우는 첫 실행 때 허용 창이 뜹니다)
- 회사·학교 와이파이는 기기끼리의 통신을 막아 두는 경우가 많습니다

### ② 세이브를 글자로 옮긴다 (한 번만 옮기면 될 때)

서버 없이도 캐릭터를 옮길 수 있습니다.

1. 원래 기기에서 **설정(⚙ 또는 `O`) → 세이브 옮기기 → 내보내기**
2. 나온 글자를 전부 복사 (`POINO1:` 로 시작합니다)
3. 새 기기에서 아무 이름으로 **새 계정**을 만든 뒤,
   **설정 → 세이브 옮기기 → 붙여넣기로 불러오기** 를 누르고 붙여 넣은 다음 한 번 더 누르기

레벨·장비·소지품·퀘스트 진행이 그대로 넘어갑니다.

## 접속과 세이브

처음 열면 접속 화면이 뜹니다. **새 계정** 탭에서 아이디·비밀번호·캐릭터 이름을 만들면
그 계정에 진행 상황이 저장되고, 다음부터는 **접속** 탭으로 이어서 시작합니다.

| 서버 상태 | 저장 위치 | 특징 |
|---|---|---|
| `node server/server.js` 실행 중 | `server/data/accounts.json` | 다른 기기·다른 브라우저에서도 이어서 가능 |
| 서버 없음 | 브라우저 `localStorage` | 그 브라우저 안에서만 유효 |

게임은 **20초마다, 그리고 중요한 변화(전투 종료·구매·강화·맵 이동)마다** 자동 저장합니다.

> **비밀번호 주의** — 이 계정은 *세이브 슬롯을 구분하기 위한 것*입니다.
> 비밀번호는 브라우저에서 SHA-256으로 해시한 값만 저장소로 나가지만, 그 해시가 곧 토큰이라
> 제대로 된 인증 체계가 아닙니다. **다른 곳에서 쓰는 비밀번호를 재사용하지 마세요.**
> 서버도 집·사내망에서 친구끼리 쓰는 용도이지, 공개 인터넷에 그대로 열어둘 물건이 아닙니다.

## 콘텐츠 배포 (아이템 표를 고치고 바로 적용하기)

아이템·드랍표·퀘스트 같은 **표를 서버에서 고치면, 접속자 화면에 곧바로 "새 버전" 알림이 뜹니다.**
게임 코드를 다시 만들 필요도, 파일을 다시 나눠 줄 필요도 없습니다.

### 폴더

```
server/content/            지금 배포 중인 표들 ← 여기를 고친다
server/content/version.json  { version, publishedAt, note }
server/content/history/v3/   배포할 때마다 남는 이전 판 스냅샷
```

서버를 처음 켜면 `src/data/` 에서 표를 한 번 복사해 옵니다.

### 가장 흔한 흐름

```bash
node server/server.js                  # 서버를 켜 둔다
# server/content/items.json 을 열어 값을 고치고 저장
#   → 서버가 감지 → 검사 → 버전 +1 → 접속자에게 알림 → "지금 적용" 누르면 반영
```

저장만 하면 끝입니다. **검사에 걸리면 배포하지 않고** 콘솔에 이유를 찍은 뒤 이전 판을 유지하므로,
오타 하나로 게임이 깨지는 일은 없습니다.

```
⚠ 콘텐츠에 문제가 있어 배포하지 않았습니다:
   · drops.json: 'slime' 이 없는 아이템 'slime_jely' 을 떨굽니다.
   고치면 자동으로 다시 시도합니다.
```

### 명령 도구

```bash
node tools/content.js status            # 지금 버전과 표 상태
node tools/content.js check             # 검사만 (CI 에 걸어도 된다)
node tools/content.js push              # src/data → server/content 복사
node tools/content.js publish "메모"     # 검사 후 버전 올려 배포
node tools/content.js release "메모"     # push + publish 한 번에
node tools/content.js history           # 남아 있는 버전 목록
node tools/content.js rollback 3        # v3 내용으로 되돌린다
```

`src/data` 에서 작업하는 게 편하면 고친 뒤 `node tools/content.js release "메모"` 한 줄이면 됩니다.

### 무엇을 검사하나

- 드랍표·퀘스트·상점·교환 레시피·직업 시작 장비가 **없는 아이템/몬스터를 가리키는지**
- 드랍 확률이 0~1 범위인지, 아이템에 `name` 이 있는지, `price`·`stats` 형식이 맞는지
- 직업이 없는 스킬 id 를 가리키는지
- JSON 문법 오류

### 클라이언트가 하는 일

1. 시작할 때 `/api/content` 로 서버 표를 받아 게임에 들어 있는 표 위에 덮어씁니다.
   서버에 없는 파일은 게임 것을 그대로 쓰므로 **표 하나만 배포해도 됩니다.**
2. 서버가 배포하면 WebSocket 으로 알림이 오고 화면 위에 띠가 뜹니다. 막힌 환경을 대비해 30초 폴링도 겁니다.
3. **"지금 적용"** 을 누르면 진행 상황을 저장하고 새로고침합니다.

접속 화면 아래에 지금 붙어 있는 콘텐츠 버전이 표시됩니다 (`서버 · 콘텐츠 v3`).

> 그림(PNG)은 이 배포에 포함되지 않습니다. 새 아이콘을 추가했다면 `assets/` 도 함께 옮기고
> `manifest.json` 을 배포하세요.

### 표를 엑셀·구글 시트에서 고치기

아이템 · 몬스터 · 드랍표 · 퀘스트 · 스킬 · **직업(패시브)** · 특성 · **스탯** · 포인트 설정 아홉 가지를
CSV 로 꺼내 스프레드시트에서 고칠 수 있습니다.

```bash
node tools/sheets.js export           # sheets/*.csv 로 꺼낸다
# 엑셀·구글 시트에서 고친 뒤
node tools/sheets.js check            # 검사만
node tools/sheets.js apply "메모"      # 반영 + 배포
```

구글 시트를 서버에 연결해 두면 시트에서 숫자만 고쳐도 알아서 반영됩니다.
자세한 건 **[SHEETS.md](SHEETS.md)**.

> **작업을 시작하기 전에는 늘 시트부터 봅니다.** 표는 두 곳에서 고쳐집니다 —
> 사람은 구글 시트에서, 작업은 `sheets/*.csv` 에서. 순서를 정해 두지 않으면
> 한쪽이 다른 쪽을 소리 없이 덮습니다. 절차는 **[SHEET-FIRST.md](SHEET-FIRST.md)** 에 있고,
> 견주는 도구는 `node tools/sheets-diff.js` 입니다.
>
> **0.43 부터 이름을 안 봅니다.** 내려받은 통합문서를 `sheets/inbox/` 에 넣어 두면
> 이름이 무엇이든(`…-0.42.0.xlsx` → `…-0.43.0.xlsx`) 가장 최근 것을 집습니다.
> `node tools/sheets.js pull` 도 마찬가지로 문서 **아이디**를 `sheets/SOURCE.txt` 에
> 기억해 두므로, 시트 이름이 바뀌어도 같은 문서를 계속 읽습니다.
> (그래서 **새 문서를 만들지 말고 같은 문서에 덮어써** 주세요.)

들여오기는 항상 검사를 먼저 통과해야 하고, 손으로 맞춰 둔 형식
(`drops.json`·`quests.json` 의 한 줄 = 한 행, `skills.json` 의 직업 구분선,
`per`·`mods`·`effect` 를 한 줄로 눕히는 것)은 그대로 지켜집니다.

스킬 시트의 `직업` 칸은 `classes.json` 의 직업별 스킬 목록을 함께 고칩니다 —
시트에서 직업을 바꾸면 정말 그 직업이 배우게 됩니다.

**패시브는 `classes` 시트입니다.** 다만 두 겹으로 나뉘어 있다는 걸 알아야 합니다:
`passive.*` 와 `combatDesc` 는 화면에 보여 줄 **글**이고, 전투를 실제로 바꾸는 것은
`combat.*` 의 숫자(`counter` `potionPower` `shieldMs` …)입니다. 시트에서는 글에 해당하는 줄에
`★` 표시가 붙어 있으니, 패시브를 세게 만들 때는 숫자와 글을 함께 고치세요.

## 함께 사냥하기 (오픈 필드)

전송 수단을 두 가지 동시에 씁니다. 하나가 없어도 나머지가 동작합니다.

| 수단 | 범위 | 조건 |
|---|---|---|
| `BroadcastChannel` | 같은 브라우저의 다른 탭 | 없음 — 탭 두 개만 열면 바로 |
| `WebSocket` | 다른 기기·다른 사람 | `node server/server.js` 실행 |

같은 맵에 있는 사람은 **이름표가 붙은 캐릭터**로 그려지고, 그 사람이 입은 장비까지 반영됩니다.
누군가 몬스터를 잡으면 다른 사람 화면에서도 그 몬스터가 사라지고, 리스폰 위치도 공유됩니다.
(몬스터의 평상시 배회 위치는 각자 계산하므로 조금씩 다를 수 있습니다.)

### 지금 붙어 있는지 화면에서 본다

화면 위쪽에 상태가 항상 떠 있습니다. 셋 중 하나입니다.

| 표시 | 뜻 |
|---|---|
| 🌐 함께 접속 N명 | 서버에 붙어 있고, **같은 맵**에 N명이 더 있다 |
| ⚠ 연결 끊김 — 다시 연결 중 | 서버는 있는데 연결이 끊겼다. 스스로 다시 붙는다 |
| 🖥 혼자 (서버 없음) | 서버를 못 찾아 이 브라우저 안에서만 놀고 있다 |

세 번째가 **PC 와 폰이 따로 노는 상황**입니다. 그 기기는 서버가 아직 깨어나기 전에 들어와
자기 브라우저에 계정을 만든 것이므로, 서버가 깬 뒤 새로고침하면 됩니다.
접속 화면에서도 서버가 깰 때까지 계속 두드려 보다가 붙으면 "서버" 로 바뀝니다.

### 가만히 서 있어도 사라지지 않는다

예전에는 위치가 **바뀔 때만** 보냈습니다. 둘 다 멈춰 서면 양쪽 다 아무것도 안 보내게 되고,
6초 뒤 서로를 "끊긴 사람"으로 지웠습니다. 지금은 2초마다 "나 여기 있다"를 보내고,
서버도 25초마다 ping 을 보내 중계기가 조용한 연결을 끊지 못하게 합니다.
연결이 끊기면 1→2→4→8→15초로 늘려 가며 스스로 다시 붙고, 폰이 절전에서 돌아오면 즉시 다시 붙습니다.

## 장비 슬롯 (10칸)

착용 칸은 세 분류로 나뉩니다. 목록은 `src/systems/EquipmentSystem.js` 의 `SLOT_GROUPS` 한 곳에만 있습니다.

| 분류 | 칸 |
|---|---|
| 무기 | 무기 |
| 방어구 | **투구** · 어깨 · 갑옷 · 장갑 · 신발 |
| 장신구 | 벨트 · 목걸이 · 반지 1 · 반지 2 |

> **투구 칸은 0.35 에서 새로 생겼습니다**(용린 세트). 옛 세이브에는 이 칸이 없지만
> `emptyEquipment()` 가 `null` 로 채워 주므로 그냥 빈 칸으로 열립니다.

아이템의 `slot` 값이 곧 칸 이름입니다(`"slot": "boots"` → 신발 칸).
예외는 반지 하나뿐으로, `"slot": "ring"` 은 **빈 반지 칸을 먼저** 채우고 둘 다 차 있으면
어느 칸에 낄지 물어봅니다. 칸을 늘리고 싶으면 `SLOT_GROUPS` 와 `SLOT_LABEL` 에 줄을 추가하면 됩니다.

소지품 창(`I`)은 **전체 · 장비 · 소모품 · 재료** 탭으로 나뉘어 있고 탭마다 개수가 붙습니다.
**탭 개수의 합은 반드시 전체와 같습니다** — 어느 탭에도 안 잡히는 아이템이 생기면
"가방에 있는데 고를 수가 없다"가 되기 때문입니다.
분류는 `items.json` 의 `type` 이 정하지만, 그 값이 이상해도 `slot` 을 보고 장비로 잡아 주는 안전망이 있고,
`node tools/print-tables.js items` 가 잘못 적힌 항목을 찾아 줍니다.

창을 다시 그려도 **목록 스크롤 위치는 그대로**입니다(`src/ui/keepScroll.js`).
아래쪽 아이템을 눌렀을 때 목록이 위로 튀면 엉뚱한 것이 골라진 것처럼 보입니다.
분류는 `systems/InventorySystem.js` 의 `CATEGORIES` 표 한 곳에만 있어서 줄 하나로 늘릴 수 있습니다.

**캐릭터 창(`C`)의 장비 탭**에서 9칸을 한눈에 보고 해제할 수 있고,
수치 옆 **`>` 를 누르면 디아블로2처럼 그 수치가 어디서 왔는지** 펼쳐 보여 줍니다
(기본 · 특성 · 장비 각각 · 비율 보너스).
### 소지품 창 — 입은 것과 안 입은 것 (0.38)

**입고 있는 것은 아이템 목록에 나오지 않습니다.** 위의 장비 띠에만 있습니다.
벗으면 그 자리에서 다시 목록에 돌아옵니다.

**목록은 소제목으로 나뉩니다 (0.40).** 전체 탭은 **장비 · 소모품 · 재료**로,
장비 탭은 **무기 · 방어구 · 장신구**로 갈라집니다. 입은 것을 숨긴 뒤에도 검·물약·약초가
이름순으로 뒤섞여 있으면 팔 것 하나 고르는 데도 처음부터 끝까지 훑어야 했습니다.
줄 수를 줄일 수는 없으니 **줄을 나눕니다.** 묶음이 하나뿐이면 소제목을 달지 않습니다.

> 예전에는 같은 물건이 위 띠와 아래 목록에 두 번 나왔습니다. 목록에서 고르고도
> "이게 지금 낀 건가"를 다시 확인해야 했고, 목록은 늘 장비 수만큼 길었습니다.
> 이제 띠는 **입은 것**을, 목록은 **아직 안 입은 것**을 맡습니다.
> (대장간·마녀 창은 예외입니다 — 거기서는 지금 낀 무기를 강화하러 오니까요.)

**장비 띠를 누르면 벗겨지지 않고 그 물건이 펼쳐집니다.** 벗는 것은 자세히 보기의
해제 버튼이 맡습니다 — 보는 것과 벗는 것은 다른 일이고, 예전에는 확인하려고
눌렀다가 벗겨지는 일이 잦았습니다.

### 체력 숫자가 길어져도 보입니다 (0.40)

왼쪽 아래 HP 구슬은 84px 짜리 동그라미인데, 체력이 다섯 자리가 되면
`48 / 15,342` 가 그보다 넓어집니다. 예전에는 구슬 전체에 자르기(overflow:hidden)가
걸려 있어서 **양끝이 잘려 나갔습니다.**

- 자르는 일은 이제 **피가 차는 안쪽**만 맡습니다. 숫자는 구슬 밖으로 조금 나가도 그대로 보입니다.
- 숫자 뒤에 **어두운 알약**을 깔아 땅 위에서도 읽힙니다.
- 자릿수가 늘면 글자를 한 단계씩 줄입니다(11자 · 14자에서).
- 가운데 맞춤은 CSS grid 에 맡기지 않고 직접 잡습니다 — 넘치는 항목을 grid 가
  왼쪽에 붙여 버려서 4px 어긋났습니다.

전투 화면의 체력 막대도 같은 이유로 자르지 않습니다. 아그라모스는 체력이 일곱 자리라
`4,937,000 / 4,937,000` 이 막대보다 깁니다.

### 갈아 끼우면 무엇이 오르나 (0.38)

아직 안 입은 장비를 고르면, **지금 그 자리에 낀 것과 견준 차이**가 함께 뜹니다.

```
공격력 +36  ▲ 23      ← 초록. 강철 검(13) 에서 화염검(36) 으로 가면 23 오른다
치명타 +5%  ▲ 3%
속도   +2   ▼ 3       ← 빨강. 내려가는 것은 이렇게 보인다
```

- 오르면 **초록 ▲**, 내려가면 **빨강 ▼**. 색과 화살표를 둘 다 씁니다 —
  색만으로 가르면 색을 못 가리는 사람에게는 아무 말도 안 하는 것과 같습니다.
- 화살표가 방향을 말하므로 숫자에는 부호를 붙이지 않습니다(`▼ 3`, `▼ -3` 이 아니라).
- 반지처럼 자리가 둘인 것은 **빈 칸이 있으면 견주지 않습니다** — 그때는 벗겨지는
  것이 없으니 그냥 더해지는 것이 맞습니다. 둘 다 차 있으면 첫 칸과 견줍니다.

**상점에서도 같은 견주기가 붙습니다 (0.39).**

```
화염검   희귀 · 공격 +36 ▲ 30 · 치명 +5.0% ▲ 5.0% · HP +66 ▲ 54
         지금 낀 것: 나무 검                              🪙 1,500
```

사기 **전에** 오르는지 내리는지가 보입니다. 예전에는 상점에 "공격 +36" 만 적혀 있어서,
지금 낀 검이 얼마짜리인지 확인하러 가방을 열었다가 다시 상점으로 돌아와야 했습니다.
견주는 규칙은 소지품 창과 **같은 한 곳**(`src/ui/gearCompare.js`)에서 나오므로,
두 화면이 서로 다른 말을 할 수 없습니다. 물약·재료에는 붙지 않습니다(견줄 자리가 없으니까요).

소지품 창(`I`)은 좁으므로 착용 중인 장비를 한 줄 띠로만 보여 줍니다.

**특성/스킬 초기화** — 캐릭터 창의 특성·스킬 탭 아래에 초기화 버튼이 있습니다.
비용은 `찍은 포인트 × 120 + 레벨 × 30 + 200` 골드이고, 되돌린 포인트는 전부 돌아옵니다
(`formulas.js` 의 `RESET_COST`).

## 옛 파일로는 못 들어옵니다

서버는 `/api/ping` 으로 **제가 들고 있는 판 번호**를 함께 알려 줍니다. 브라우저가 캐시에 붙잡아 둔
옛 파일로 열면 그 번호가 다르고, 그러면 접속 화면 맨 위에 띠가 뜨고 **접속 버튼이 잠깁니다.**

```
0.35.0 버전이 새로 나왔습니다
지금 열려 있는 파일은 v0.33.0 입니다.
[ 새로 받아서 다시 열기 ]
```

왜 막기까지 하느냐 — 옛 파일로도 로그인은 됩니다. 그러고 나서 새로 생긴 아이템을 주우면
**'없는 아이템'으로 지워지고 그 상태가 그대로 저장됩니다.** 들어가기 전에 멈추는 편이 낫습니다.
'새로 받아서 다시 열기'는 주소 뒤에 값을 하나 붙여 캐시를 비껴갑니다.

| 그만하기 | **접속 화면으로** · **종료** — 둘 다 저장하고 나갑니다 |

### 화면 방향 — 자동 / 가로 고정 / 세로 고정

폰을 세워 들면 판이 **480×640** 으로 바뀝니다(가로일 때는 640×480).

왜 판 크기를 바꾸느냐 — 스테이지는 통째로 축소됩니다. 폭이 390 인 폰에서 640 짜리 판을
그대로 두면 **0.61 배**로 줄어 글씨까지 작아지는데, 아래위로는 빈 자리가 잔뜩 남습니다.
폭을 480 으로 줄이면 같은 폰에서 **0.81 배**가 되어 3분의 1쯤 크게 보입니다.
"세로면 무조건 가로로 돌리라"고 하던 안내도 그래서 없앴습니다.

| 값 | 언제 |
|---|---|
| **자동**(기본) | 화면이 세로로 길면 세로 판, 아니면 가로 판 |
| **가로 고정** | 폰을 세워 들어도 가로 판 |
| **세로 고정** | 폰을 눕혀도 세로 판 |

바꾸면 **그 자리에서** 바뀝니다. 캔버스 크기도 함께 바뀌므로 보이는 범위가 실제로 달라집니다
(`core/Viewport.js` 가 `--w`/`--h` 와 `renderer.setViewSize` 를 함께 움직입니다).

### 그만하기 — 접속 화면으로 · 종료

설정 맨 아래에 있습니다. **둘 다 먼저 저장한 뒤** 나갑니다.
'접속 화면으로'는 새로고침이라 다른 아이디로 바꿔 접속할 수 있고,
'종료'는 창을 닫습니다 — 브라우저가 창 닫기를 막으면(스스로 연 창이 아닐 때) 그렇다고 알리고
접속 화면으로 보냅니다. 아무 일도 안 일어나면 "버튼이 고장났다"로 읽히기 때문입니다.

### 창을 열면 시간 멈춤

상점이나 소지품을 보는 동안 **세상의 시계를 세울지** 고르는 항목입니다. 기본은 **켬**입니다.

| | 켬 (기본) | 끔 |
|---|---|---|
| 회복·버프·되살아남 | 멈춥니다 | 계속 흐릅니다 |
| 화면 | 조용합니다 | 체력이 찰 때마다 일부가 다시 그려집니다 |

어느 쪽이든 **내 발과 몬스터의 발은 멈춥니다** — 그렇지 않으면 상점 목록을 보는 사이에
늑대가 걸어와 전투가 시작되고, 사람은 무슨 일이 일어났는지 알 수 없습니다.

> 원래는 "창을 열어도 시간이 흐르게" 만들었는데, 그러면 체력이 찰 때마다 화면이
> 다시 그려져 **깜빡이는 것처럼** 보인다는 이야기가 있었습니다. 다시 그리는 횟수를
> 초당 20번에서 4번으로 줄이고 창마다 덧그림 방지 자물쇠를 달았지만, 그래도 거슬린다면
> 예전처럼 아예 멈추는 편이 낫다고 보아 **기본을 멈춤으로 되돌렸습니다.**
> 시간이 흐르는 쪽이 좋다면 이 항목을 끄면 됩니다.

## 전투 화면 (0.53)

### 화면을 통째로 덮습니다

씬은 스택 전체를 아래에서부터 그립니다 — 전투 아래에 **필드가 그대로 있습니다.**
그런데 배경 그림은 640×480 인데 세로 화면은 480×640 이라, 그림을 왼쪽 위에 그대로
놓으면 **아래 160px 이 안 덮여 필드가 비쳐 보였습니다.** 전투 중에 뒤에서 몬스터가
걸어 다니면 눈이 그리로 갑니다.

```js
// scenes/BattleScene.js
ctx.fillStyle = '#0b1020'; ctx.fillRect(0, 0, W, H);       // ① 먼저 통째로 지운다
const k = Math.max(W / bg.w, H / bg.h);                     // ② 넘치게(cover) 키워
renderer.drawSprite('bg_battle_field', (W - bg.w * k) / 2, (H - bg.h * k) / 2, { scale: k });
```

①이 있어서 그림이 없거나 못 불러와도 필드는 안 비칩니다.

### 전투 글은 한 줄입니다

예전 줄:

```
슬라임의 공격! 아무개에게 23 데미지 (치명타! · 흡혈 +4 · 분노 2중첩)
```

이름 둘에 꼬리표 넷. 세로 화면에서는 두세 줄로 접히고 다음 줄이 곧바로 올라와서
**읽기도 전에 지나갔습니다.** 누가 누구를 때렸는지는 화면에 이미 보이므로
(그림이 움직이고 숫자가 뜹니다) 글에는 **얼마나**와 **무엇으로**만 남깁니다.

```
23 데미지를 주었다 (치명타!)
17 데미지를 입었다
피했다
HP +55 회복 (회복약)
```

- 꼬리표는 **앞의 둘까지만** — 셋을 넘기면 다시 두 줄이 됩니다.
- 세로 화면에서는 글 상자를 **단축칸 위**로 올립니다. 폭이 480 뿐이라 나란히 두면
  물약 칸 뒤로 들어가 반쯤 잘렸습니다.

## 막혔을 때 — 물음표 안의 세 버튼

마을에서 이따금 발이 안 떨어진다는 이야기가 있었습니다. HUD 의 **?** 를 누르면 조작법 아래에
빠져나오는 길이 셋 있습니다.

| 버튼 | 하는 일 |
|---|---|
| **조작 되살리기** | 열려 있는 창을 전부 닫고, 시전을 취소하고, 전투 화면에 갇혀 있으면 필드로 되돌리고, 누르고 있던 키를 놓습니다 |
| **마을에서 다시 시작** | 위를 다 한 뒤 마을 입구로 옮기고 저장합니다 |
| **다시 접속** | 저장하고 새로고침합니다 |

**사람이 누르기 전에 게임이 먼저 알아챕니다.** 창도 안 열려 있고 대화도 아니고 전투도 아닌데
조작만 꺼져 있으면, 1.5초 뒤 스스로 되살리고 그렇게 했다고 알립니다.
원인이 하나가 아니어서(창 여닫는 짝이 어긋남 · 대화가 알림 없이 닫힘 · 시전이 중간에 멈춤)
**원인마다 고치는 대신 언제든 되살아나게** 만들어 두었습니다.

## 장비 외형 (파츠 레이어)

장비를 바꾸면 캐릭터 그림이 실제로 바뀝니다. 두 겹으로 동작합니다.

기본 캐릭터는 **나시(민소매) + 반바지 + 맨팔** 차림입니다. 무기·망토·소매는 기본 그림에 없고,
장비를 입을 때 레이어로 얹힙니다.

1. **색 리맵** — 상의(파랑) 영역만 골라 갑옷 색으로 갈아끼웁니다. 원래 픽셀의 밝기 비율을
   유지하므로 음영이 살아 있고, 살색·머리색은 규칙에서 제외돼 절대 물들지 않습니다.
2. **파츠 레이어** — 망토는 몸 뒤에, 소매·견갑·비늘은 몸 앞에 그려집니다.
   무기는 손 위치에 `club / sword / greatsword` 실루엣으로 그려지고, 화염검·마검은 빛이 감돕니다.
   반지는 발밑에 오라 고리를 만듭니다.

```
초기(나시+반바지+몽둥이) → 천옷(소매) → 가죽(갈색+망토) → 기사(은색+견갑+파란 망토)
                                                        → 용린(녹색 비늘+금색 망토)
```

무엇을 무슨 색으로 바꿀지는 **`src/data/appearance.json`** 에만 적혀 있습니다.
새 갑옷을 추가하면 여기에 두 줄 더하는 것으로 외형이 붙습니다.

```jsonc
"dragon_mail": { "tunic": [58,138,96], "cape": [196,150,52], "parts": ["sleeves","pauldron","scale","cape"] }
```

### 공개 서버를 견디게 하려고 한 일

예전 이 문서에는 "집에서만 쓰고 공개 인터넷에 올리지 말 것"이라고 적혀 있었습니다.
그 경고를 지우려면 실제로 고쳐야 할 것들이 있었습니다.

| 문제 | 어떻게 했나 |
|---|---|
| 비밀번호 해시가 곧 세션 토큰이었다 | 서버가 소금과 함께 PBKDF2 로 한 번 더 굳혀서 보관하고, 토큰은 따로 발급 (`server/auth.js`) |
| 서버가 잠들면 모두 로그아웃됐다 | 토큰을 저장하지 않고 서버 비밀키로 **서명**한다 — 재시작을 견딘다 |
| `/server/data/accounts.json` 이 그대로 받아졌다 | `server/` 는 정적 파일로 절대 내주지 않는다 |
| 비밀번호를 기계로 찍어 볼 수 있었다 | 가입·로그인·저장에 횟수 제한 |
| 계정을 무한정 만들 수 있었다 | `MAX_ACCOUNTS` 상한. `0` 으로 두면 기존 계정만 쓰고 새 가입을 막는다 |
| 아이디 존재 여부가 새어 나갔다 | 없는 계정과 틀린 비밀번호에 같은 문구로 답한다 |

그래도 이 계정은 **세이브 슬롯 구분용**입니다. 다른 곳에서 쓰는 비밀번호를 재사용하지 마세요.

## 월드 구조

```
              ┌───────────────────────┐
              │  지하감옥 1~5층        │  ← 옥좌 뒤 계단 · 레벨 40 이상
              │  캄캄함 · 계단 자리 랜덤 │     보석이 나오는 유일한 곳
              └───────────△───────────┘
                    ┌─────┴───────┐
                    │  포이노 성   │  ← 레벨 25 · 오른쪽 아래 무기상 카일
                    └──────△──────┘
                           │ 성문      (성 안 오른쪽 아래에 무기상 카일)
      ┌────────────────────┴────────────────────┐
 서쪽 │           포이노 마을 (40×32)             │──→ 동쪽 문
 문 ←─│  잡화점 · 대장간 · 연금술사 · 여관 · 촌장  │      │
      │  마녀 이올린 ☾ · 광장 ◈ 웨이포인트 돌      │      │
      └─────────────────────────────────────────┘      ↓
      ↓
 ┌──────────────────────┐
 │  서쪽 절벽 들판        │  ← 아무것도 없음
 │  30분마다 고룡 카르나크 │     용의 징표를 떨군다
 └──────────────────────┘
                                                   동쪽 들판 ↓
   1 → 2 → 3 → 4 → [5 BOSS]🔒 6 → 7 → 8 → 9 → [10 BOSS]🔒
                                                   │
   11 → 12 → 13 → 14 → [15 BOSS]🔒 16 → 17 → 18 → 19 → [20 BOSS] ■ 끝
        각 단계 40×32, 서/동 양쪽에 다음 단계로 가는 문
        🔒 = 그 보스를 잡고 퀘스트까지 마쳐야 열린다
        ■  = 20단계에는 동쪽 문이 없다(여기가 동쪽 들판의 끝)
```

- **마을(poino)** — 손으로 그린 격자. 몬스터가 나오지 않습니다.
  가게마다 드래곤퀘스트6처럼 **문 옆 벽에 간판**이 붙어 있습니다
  (잡화점 = 물약병 · 대장간 = 검과 망치 · 연금술사 = 플라스크 · 여관 = 침대).
  **연금술사 집은 무기점(대장간) 바로 아래**에 있고, 간판 그림은 `tools/art-gear.js` 에서 만듭니다.
- **필드 1~10단계** — `seed` 기반 자동 생성. 단계마다 `power`(몬스터 배율)와
  `levelBonus`(표시 레벨)가 올라가고 등장 몬스터 종류가 바뀝니다.
- **필드 11~20단계 (심층)** — 1~10단계와 **똑같은 땅, 똑같은 몬스터 그림**을 되풀이합니다.
  다만 이름이 `강화된 슬라임` 처럼 바뀌고 훨씬 셉니다. 지형 씨앗까지 같은 값을 쓰므로
  "11단계는 1단계와 같은 들판"이라는 감각이 그대로 남습니다.
  단계 배율은 손으로 찍은 값이 아니라 **목표 전투력에서 역산**합니다 —
  11단계 **2,500** 에서 시작해 20단계 **40,000** 까지 오릅니다.
  `tools/gen-maps.js` 의 `STAGES`/`DEEP_POWER` 에 들어 있고,
  값은 `node tools/zone-solve.js` 가 구간 설계에서 거꾸로 찾아 줍니다.

  > **예전에는 11단계가 10단계 보스보다 약했습니다.** 강화된 슬라임의 공격력이 121 인데
  > 바로 앞 단계 보스인 발가르가 246 이었으니, "강화된 땅"에 들어섰는데 오히려
  > 편해지는 구간이었습니다.
  >
  > 원인이 둘이었습니다. ① 심층 몬스터의 밑값이 원래 몬스터에서 불려 온 것이라
  > **체력만 크고 공격력이 안 따라왔고**(체력 2,330 에 공격 121),
  > ② 단계 배율이 1.0 에서 시작해 11단계가 곧 "배율 없음"이었습니다.
  >
  > 지금은 밑값의 공격/체력 비율을 다시 잡고(공격을 크게, 체력은 덜) 배율을 역산합니다.
  > 11단계 잡몹은 **전투력 2,500 · 공격 320** 으로, 10단계 보스(1,679 · 246)보다 셉니다.
  > 그래서 11단계는 **26레벨쯤** 되어야 사냥터로 쓸 수 있습니다.

  드랍도 강화된 땅답게 바뀌었습니다 — **마력석과 악마의 핵 위주**입니다.
  슬라임 젤리·박쥐 송곳니 같은 1단계 재료는 뺐습니다. 여기까지 온 사람에게
  1단계 재료를 주면 온 보람이 없고, 그 재료는 이미 남아돕니다.
- **5·10·15·20단계 보스** — 필드 동쪽 끝 근처에 배치되며 붉은 원과 `BOSS` 표시가 붙습니다.
  **보스가 있는 들판은 화산 지형으로 갈아입습니다** — 배경이 어두워지고, 풀은 잿더미,
  물은 마그마, 바위는 검은 현무암, 나무는 타 버린 둥치가 됩니다.
  땅 자체는 다른 들판과 **완전히 같습니다**(씨앗도 같습니다). 타일 글자만 바꿔 칠하므로
  길과 덤불 배치가 그대로라, 같은 길인데 다른 땅이라는 게 눈으로 보입니다.
  테마 표는 `maps.json` 의 `themes` 한 줄이고, 칠하는 곳은 `MapSystem.buildMap` 입니다.
  잡은 뒤 **1분** 뒤에 돌아옵니다(아래 참고).
  보스가 주는 **무기·방어구는 퀘스트 보상 쪽**으로 옮겼고, 드랍은 **장신구(반지·목걸이·허리띠) 위주**입니다.
  - 5단계 · 악마 정찰대장 → 나무 부적 / 가죽 허리띠 / 질풍의 반지 / 마력석
  - 10단계 · 악마 장군 발가르 → 격노의 반지 / 수호의 목걸이 / 마력의 허리띠 / 악마의 핵
  - 15단계 · 강화된 악마 정찰대장 → 룬 목걸이 / 룬 허리띠 / 희귀 회복약
  - 20단계 · 강화된 악마 장군 발가르 → 용의 인장 / 룬 장신구 / 악마의 핵 다발
- **지하감옥(dungeon_1 ~ dungeon_5)** — 성 옥좌 뒤 계단으로 내려갑니다. **레벨 40 이상**.
  들판이 아니라 **손으로 그린 방과 복도**이고, 층마다 계단으로 이어집니다.
  **보석이 나오는 유일한 곳**이며, 20단계를 다 깬 사람을 위한 자리라 매우 셉니다.

  | 층 | 이름 | 단계 보정 | 사는 것 |
  |---|---|---|---|
  | 1 | 무너진 감방 | ×1.9 | 강화된 해골 병사 · 강화된 악마 병사 |
  | 2 | 물 고인 복도 | ×2.4 | 강화된 악마 병사 · **지하의 망령** |
  | 3 | 석상의 방 | ×3.0 | 지하의 망령 · **감옥 석상** |
  | 4 | 봉인된 층 | ×3.8 | 감옥 석상 · **봉인된 장군 발가르** |
  | 5 | 주인의 자리 | ×4.8 | **감옥의 주인**(보스) |

  1층은 17단계쯤이라 레벨 40에 들어와도 버틸 수 있지만, 3층부터는 20단계 장비를
  +9 이상 올리고 오지 않으면 통하지 않습니다. 5층의 **감옥의 주인**은 이 게임에서
  가장 센 상대입니다 — Lv.50 · +10 기준으로도 서넛에 하나쯤 이깁니다.
  지도는 `tools/gen-dungeon.js` 가 씨앗을 받아 방과 복도를 그려 넣습니다.

  **올라가는 계단이 보입니다 (0.40).** 예전에는 내려가는 계단만 그림이 있고 위로 나가는
  자리는 맨바닥이라, 1층에서 성으로 돌아가는 길을 못 찾고 헤매는 일이 있었습니다.
  이제 다섯 층 모두 나가는 자리에 **위로 열린 계단**이 그려져 있습니다.

#### 보스가 보스답게 때립니다 (0.40)

층을 내려갈수록, 그리고 보스일수록 **한 대가 더 아파야** 합니다. 0.39 까지는 그렇지
않았습니다 — 표의 공격력만 보면 고룡이 제일 세 보였지만, 지하감옥 몬스터는 맵 배율을
곱해 맞으므로 실제로는 5층 보스가 고룡보다 세 배 넘게 때렸습니다.

레벨 50 · 룬 한 벌 +10 인 몸이 **한 대에 받는 피해**로 재면 이렇습니다
(`node tools/boss-atk.js` 가 이 표를 그대로 뽑습니다).

| 상대 | 0.39 | **0.40** |
|---|---|---|
| 4층 쫄 · 감옥 석상 | 1,161 | 1,161 |
| **4층 보스 · 봉인된 장군** | 2,610 | 2,461 |
| 5층 쫄 · 감옥 석상 | 1,712 | 1,712 |
| **5층 보스 · 감옥의 주인** | 1,602 | **2,669** |

  거기에 **에메랄드와 오닉스**를 새로 넣었습니다 — 방어구와 장신구의 초월 강화에 쓰는
  보석인데 정작 이 게임에서 가장 센 상대가 안 떨구고 있었습니다.
  (0.41 에서 보석 개수를 두 배로 했다가 **0.42 에서 원래대로 되돌렸습니다** —
  루비·사파이어·에메랄드·오닉스·다이아몬드 1~2개, 자수정 1개.)
- **고룡은 열 배 가까이 세졌습니다**(1,050 → 7,000). 예전에는 잘 갖춘 사람이 혼자서도
  100% 눕혔습니다 — 여럿이 함께 때리라고 만든 상대인데 그럴 이유가 없었던 셈입니다.
  지금은 혼자서는 잘 못 눕히고, 대신 **물어뜯어 놓은 상처는 그대로 남습니다.**

  **지하감옥은 들판과 규칙이 다릅니다.**

  - **캄캄합니다.** 횃불이 닿는 **3~4칸**만 보입니다. 그 밖의 몬스터는 그리지도 않으므로
    정말로 보이지 않습니다(어둠막만 덮으면 검은 실루엣이 비쳐서 소용이 없습니다).
  - **내려가는 계단 자리가 매번 다릅니다.** 들어올 때마다 다른 방에 놓이므로,
    층마다 계단을 찾아 헤매는 일이 곧 탐험이 됩니다. 들어온 방에는 놓이지 않습니다.
  - **몬스터가 알아채고 달려듭니다.** 5칸 안에 들어가면 머리 위에 빨간 **!** 가 뜨고
    쫓아옵니다. 한 번 들키면 한참 멀어질 때까지 따라오고, 쫓는 동안은 눈에 띄게 빨라집니다.
    벽을 만나면 **돌아서 옵니다** — 길찾기를 하므로 벽 뒤에 숨는다고 안전하지 않습니다.
  - **한 판에 여러 마리가 붙습니다.** 한 마리 60% · 두 마리 35% · 세 마리 5%.
    5층은 예외로 **주인 하나뿐**입니다.

### 서쪽 절벽 들판과 고룡 카르나크

마을 **서쪽** 문으로 나가면 아무것도 없는 절벽의 들판이 있습니다.
나무도 몬스터도 상점도 없습니다. 사방이 낭떠러지이고 가운데가 텅 비어 있습니다.
그 빈 자리에 **30분마다 한 번** 고룡이 내려앉습니다.

| | |
|---|---|
| **언제** | 30분마다 내려앉아 **25분간 머물다 떠납니다.** 나머지 5분은 절벽이 비어 있습니다 |
| **세기** | Lv.10 까지는 한 대도 못 깎습니다. **Lv.40 · +9** 쯤에서 한 판에 10% 정도를 깎습니다 |
| **몇 번** | 그래서 **열 번쯤 붙어야** 눕습니다 |
| **상처가 남는다** | 못 잡아도 깎아 둔 체력이 **그대로 남습니다.** 접속을 끊었다 와도 남아 있습니다 |
| **져도 잃는 것이 없다** | 골드를 뜯기지 않습니다. 무조건 **마을에서 눈을 뜹니다** |
| **몫** | 피해를 많이 준 순서로 징표 **1등 3개 · 2등 2개 · 나머지 1개.** 우편으로 옵니다 |
| **바닥에는 아무것도** | 고룡은 **드랍이 없습니다.** 경험치·골드까지 전부 우편으로만 나갑니다 |
| **분노** | 한 번 휘두를 때마다 공격력이 **10% 씩 붙습니다.** 오래 끌수록 무서워집니다 |

#### 분노 — 오래 끌면 안 되는 상대

고룡은 판이 길어질수록 세집니다. 한 번 때릴 때마다 공격력에 **×1.1** 이 곱해집니다
(누적이므로 5번째 휘두름은 1.1⁴ ≈ **1.46배**, 10번째는 1.1⁹ ≈ **2.36배**).

전투 기록에는 `분노 N중첩` 이라고 함께 찍힙니다 — 갑자기 아파진 이유가 보여야 하니까요.
"버티면 이긴다"가 안 통하는 유일한 상대이므로, **길게 버티는 몸**보다
**짧게 많이 깎는 몸**이 유리합니다.

> 표에서 고치는 값입니다 — `sheets/monsters.csv` 의 **분노** 칸(`monsters.json` 의 `rage`).
> 0 이면 예전과 똑같이 굴러갑니다. 다른 몬스터에도 붙일 수 있습니다.

**마을에 있으면 알려 줍니다.** 용이 와 있는 동안 마을에 서 있으면
"서쪽에서 이상한 기운이 감돈다..." 라는 말이 뜨고, 몇 분 남았는지 함께 알려 줍니다.
25분만 머무는 상대라 절벽까지 걸어가 봐야 아는 것이면 헛걸음이 되기 때문입니다.
같은 마리를 두고 되풀이해 알리지는 않습니다.

**절벽에 들어서면 상태 줄이 뜹니다.** HUD 왼쪽에 남은 체력 막대와
"몇 분 뒤 떠남"이 함께 붙습니다. 남은 시간은 1초마다 줄어들고,
서버에 붙어 있으면 **남이 때린 만큼도** 12초마다 받아 와 반영됩니다.
여기 서 있는 동안 알고 싶은 것은 둘뿐이라서요 — 몇 번을 더 붙어야 하나,
지금 마을에 다녀올 틈이 있나. 시간이 다 되면 눈앞에서 날아가 버립니다.

**눕히면 그 자리에서 등수를 알려 줍니다.** 참여한 사람들의 누적 피해와
각자의 몫이 함께 뜨고, 몫은 우편으로 갑니다. 남이 마무리했더라도
"고룡이 쓰러졌다"는 알림이 뜨므로 눈앞에서 사라진 이유를 알 수 있습니다.

**서버에 접속해 있으면 체력을 서버가 들고 있습니다.**
여럿이 **같은 놈**을 때리고, 마지막 일격이 아니라 **누적 피해**로 몫이 갈립니다.
한 대라도 때린 사람은 빈손으로 돌아가지 않습니다 — 그래야 여럿이 달려듭니다.
혼자 할 때는 내 세이브의 값이 곧 진실입니다(그때는 겨룰 상대가 없으니까요).

### 두 번째 고룡 — 잠긴 동굴의 아그라모스 (0.37)

서쪽 절벽 **서쪽 끝**에 큰 동굴문이 하나 있습니다. 자물쇠가 걸려 있어 그냥은 안 열립니다.

```
용의 징표 10개  →  마녀 이올린에게서 용의 열쇠  →  서쪽 절벽 서쪽 끝의 문  →  고룡의 둥지
```

- **열쇠는 없어지지 않습니다.** 한 번 열면 계속 열려 있습니다 — 매번 징표 열 개를
  다시 모으게 하면 그 상대는 사실상 한 번만 만날 수 있는 상대가 됩니다.
- 카르나크와 달리 **시간에 맞춰 오지 않습니다.** 늘 거기 있고, **잡으면 한 시간 뒤**에
  온전한 몸으로 다시 섭니다.

| | 고룡 카르나크 | 잠겨 있던 용 아그라모스 |

| 언제 | 30분마다 와서 25분 머문다 | 늘 있다 · 잡으면 **1시간** 뒤 |
| 세기 | 지하감옥 주인의 0.12배 | 지하감옥 주인의 **2.00배** |
| 상처 | 남는다(여럿이 함께 깎는다) | 남는다(혼자 몇 번이고 물어뜯는다) |
| 보상 | 누적 피해에 따라 우편으로 | 그 자리에서 — 아래 |

**보상** — 골드 **1,125만~1,875만**, 보석 **14~28개**(일곱 가지에서 2~4개씩),
재료 **100~200개**(마력석 40~80 · 악마의 핵 40~80 · 약초 20~40).

#### 왜 상처가 남게 두었나

지하감옥 주인의 **두 배**로 세게 두라는 요청이었습니다. 그런데 그대로 두고 재 보니
**용린 한 벌을 다 갖춘 만렙으로도 승률이 0%** 였습니다 — 한 판에 눕히는 것이
어떤 장비로도 불가능했습니다. 갈 수는 있는데 잡을 수는 없는 자리가 되는 것입니다.

그래서 서쪽 절벽의 카르나크와 같은 방식을 씁니다 — **깎아 둔 만큼 남습니다.**
그러면 "두 배" 를 지키면서도 잡을 수 있는 상대가 됩니다. 실제로 재 보면 이렇습니다
(`node tools/dragon2.js`).

| | 한 판에 깎는 몫 | 눕히기까지 |
|---|---|---|
| 용린 한 벌 (4세트 효과 켜짐) | 67~100% | **1~2번** |
| 룬 한 벌 (세트 효과 없음) | 2~4% | 25~48번 — 사실상 못 눕힌다 |

> **0.38 에서 빨라졌습니다.** 예전에는 2~5번이었는데, 용린 4세트가 이 상대 앞에서
> 힘·민첩·지능을 +100 한 뒤 다시 200% 올려 주게 바뀌었습니다.
> 이 자리의 문턱은 **싸움의 길이가 아니라 준비물**입니다 — 징표 열 개, 열쇠, 그리고 한 벌.
> 거기까지 온 사람에게 전투를 길게 끌 이유가 없습니다.

**이 상대는 용린 4세트를 갖추라고 있는 상대입니다.** 그래서 져도 값을 치르지 않습니다 —
몇 번이고 붙어야 눕는 상대에게 질 때마다 골드를 뜯기면 도전 자체가 손해가 됩니다.

> **세 번째 고룡을 넣으려면** `monsters` 표에 줄 하나, `maps` 에 방 하나,
> 그리고 `affixes.json` 의 용린 4세트 `상대` 줄에 id 하나를 더하면 됩니다.
> 코드는 건드릴 것이 없습니다.

> **고룡은 바닥에 아무것도 흘리지 않습니다.** 드랍표가 아예 비어 있고,
> 잡았을 때 주던 경험치·골드도 그 자리에서는 나오지 않습니다.
>
> 흘리면 **마지막 일격을 넣은 사람이 다 가져갑니다.** 스무 번을 함께 두들긴
> 사람이 빈손이 되면 여럿이 달려들 이유가 사라집니다. 그래서 값어치는 전부
> 서버가 기여도대로 갈라 우편으로 보냅니다 — 징표는 등수대로(3·2·1),
> 경험치와 골드는 **입힌 피해의 비율대로**.
> (수치는 `server/server.js` 의 `DRAGON.reward`, 환경변수 `DRAGON_EXP`·`DRAGON_GOLD`)

- 잡으면 그 자리는 **다음 30분 주기까지 비어 있습니다.** 새 용은 온전한 몸으로 옵니다.
- 시각은 시계에 맞춰 계산하므로(`Math.floor(now / 30분)`), 여러 명이 같이 해도
  "지금 와 있다"가 서로 같습니다.
- **고룡에게는 기세(±35%)를 걸지 않습니다.** 남은 체력을 판마다 이어 붙이는 상대에게
  기세를 걸면, 체력이 적게 굴러 나온 판의 값이 그대로 "깎은 것"으로 기록되어
  한 대도 안 때리고 20%를 벗겨 내게 됩니다(실제로 그런 버그가 있었습니다).

### 보스 연출 (0.47 → 0.48)

보스와 붙으면 곡이 바뀌는데 화면은 그대로여서 "이게 보스인가" 가 안 보였습니다.
이제 화면이 어두워지고 이름표가 들어왔다 나갑니다. **세 갈래**입니다.

| 언제 | 어떻게 | 얼마나 |
|---|---|---|
| 보통 보스 등장 | 붉은 이름표가 **가로질러** 들어온다 · `보스` | 1.7초 |
| **고룡 등장** (0.48) | 그림이 **아래에서 솟아오른다** · 화면을 통째로 · `고룡` | 2.8초 |
| **쓰러졌다** (0.48) | 푸른 이름표가 **가라앉는다** · 그림은 잿빛 | 1.6초 |

셋이 **서로 다른 방향으로 움직입니다.** 같은 움직임에 색만 바꾸면 이겼는지 졌는지가
눈에 안 들어옵니다. 고룡은 30분에 한 번 오는 상대라 다른 보스와 같은 배너로 나오면
"그냥 조금 센 놈" 으로 보입니다 — 그래서 그림이 190px 로 커지고 이름이 44px 이 됩니다.

**대사도 한 줄씩 붙습니다** (0.48). `monsters` 시트의 **`등장대사`** 와 **`쓰러질때`** 칸입니다.

```
고룡 카르나크   등장 · 작은 것이 왔구나. 숨 한 번이면 될 것을.
              쓰러짐 · …재미있었다. 오랜만에.
감옥의 주인     등장 · 내려온 자는 많았다. 올라간 자는 없었고.
              쓰러짐 · 올라가라. 위에서 무엇을 볼지는… 모르지만.
```

비워 두면 대사만 안 붙고 연출은 그대로 돕니다. **잡몹 줄은 비워 두세요** —
매번 말하면 사냥이 시끄러워집니다.

규칙 셋:

- **보스일 때만.** 잡몹마다 뜨면 사냥하는 내내 화면이 덮입니다.
- **'전투 화면 건너뛰기' 를 켜 두었으면 안 뜹니다.** 그 사람은 연출을 안 보겠다고 한 것입니다.
- **도는 동안 전투가 멈춥니다.** 안 그러면 배너 뒤에서 첫 대가 오가고, 배너가 걷히면
  이미 피가 깎여 있습니다. 스킵을 누르면 배너도 함께 걷힙니다.

쓰러짐 연출은 **결과창보다 먼저** 옵니다. 결과창을 먼저 띄우면 그 위에 배너가 겹쳐
둘 다 안 읽힙니다.

소리도 셋으로 갈립니다 — 보스 울음(`bossroar`) · 고룡 울음(`dragonroar`, 더 낮고 길다) ·
쓰러지는 소리(`bossfall`, 울음과 **반대로** 아래로 떨어진다).
고룡을 크게 만들려고 소리를 키우는 대신 **아래로 내리고 늘였습니다** — 낮은 소리는 몸으로 듣습니다.

### 계정 지우기 (0.46)

운영자 창에 **계정** 단이 생겼습니다. 고른 사람을 통째로 지웁니다.

| | 무엇 |
|---|---|
| 지워짐 | 계정(아이디·비밀번호) · 세이브 · 우편함 · **랭킹에 올라간 기록**(지난 시즌 표 포함) |
| 남음 | 같은 아이디로 **다시 가입할 수 있습니다**. 그때는 새 사람입니다 |

**목록은 만든 때가 새것부터 나옵니다** (0.47). 줄마다 이렇게 붙습니다:

```
tester3    접속 오늘 17:17 · 만듦 오늘 17:16
tester1    접속 어제 21:03 · 만듦 8/20
admin      접속 없음
```

**마지막 접속을 늘 적습니다** (0.48). 이 목록을 보며 묻는 것은 거의 언제나
"이 계정 아직 쓰나" 이고, 그 답은 마지막 접속이기 때문입니다.
만든 때는 그와 **다를 때만** 덧붙습니다 — 갓 만든 계정에 같은 시각을 두 번 적으면
줄만 길어지고 아무것도 안 알려 줍니다.

마지막 접속은 **들어올 때만** 적습니다. 저장할 때마다 적으면 놀고 있는 사람 때문에
몇 초마다 계정을 다시 쓰게 됩니다. "마지막 접속" 은 놀던 시각이 아니라 들어온 시각이라
이걸로 충분합니다. (만든 때를 안 적던 시절의 옛 계정은 맨 아래에 아이디순으로 모입니다.)

전체 초기화와 다릅니다 — 그쪽은 모두를 **되돌릴 뿐** 계정을 없애지 않습니다.
시험하며 만든 계정이 쌓여 우편 고르기 목록과 랭킹을 채울 때 쓰는 것입니다.

막아 둔 것 셋:

- **운영자 자신은 목록에 안 나옵니다.** 지우면 그 순간 이 창을 열 사람이 없어집니다
  (서버도 따로 거절합니다 — 화면만 막아 두면 화면을 건너뛴 요청이 통합니다).
- 고른 사람을 **이름과 아이디로 다시 한 번** 보여 준 뒤에 묻습니다.
- `계정 삭제` 라고 직접 쳐 넣어야 단추가 열립니다. 고른 사람이 바뀌면 그 글자도 지워집니다.

> **랭킹에서 빼는 것이 핵심입니다.** 계정만 지우면 **주인 없는 1위**가 표에 남습니다.
> 그 아이디로 누가 다시 가입하면 남의 기록이 제 것이 되고, 지운 사람이 계속 순위표에
> 보입니다. 그래서 지금 시즌 표와 '지난 시즌' 표 양쪽에서 함께 뺍니다.

### 시즌 다루기 (0.45)

랭킹은 **시즌**으로 끊깁니다. 전체 초기화를 누르면 지금 표가 통째로 '지난 시즌' 으로
옮겨지고 번호가 한 칸 올라갑니다.

그런데 **아직 시험 중인 서버**에서는 그게 곤란합니다. 값을 고치며 초기화를 몇 번 하다
보면 시즌만 5, 6 으로 올라가고 정작 "1 시즌 기록" 은 영영 안 남습니다.
그래서 운영자 창 랭킹 단에 두 가지를 두었습니다.

| | 무엇 |
|---|---|
| **시즌 고정** | 켜 두면 **어떤 초기화도 시즌을 안 넘깁니다.** 기록과 세이브만 지워지고 번호는 그 자리입니다. 켜져 있으면 상자가 초록으로 바뀌고 초기화 단추 글도 "(시즌 그대로)" 로 바뀝니다 |
| **1 시즌으로 되돌리기** | 이미 올라가 버린 번호를 1 로 내립니다. **기록도 세이브도 안 지웁니다** — 번호와 '지난 시즌' 만 되돌립니다. 확인 글자로 `1 시즌` 을 적어야 열립니다 |

고정을 켜면 '지난 시즌' 표도 **안 만듭니다.** 있지도 않았던 과거가 랭킹 창에 남으면
그 창이 거짓말을 하기 때문입니다.

되돌리기는 **아직 못 본 시즌 알림도 함께 치웁니다.** 안 그러면 자고 있던 사람이
들어와서 "3 시즌이 시작되었습니다" 를 보게 됩니다 — 표에는 1 시즌이라고 적혀 있는데요.

> ### 시즌 번호가 한 살씩 많았습니다 (0.45 에서 고침)
>
> 전체 유저 초기화가 알려 주는 번호와 접속할 때 뜨는 알림이 **랭킹 창보다 하나 컸습니다.**
> 예전에는 세이브를 먼저 지우고 랭킹을 나중에 넘겼는데, 그 순서가 바뀌면서
> "이미 올라간 번호" 에 +1 을 한 번 더 하고 있었습니다.
> 랭킹 창은 2 시즌인데 알림만 "3 시즌" 이라고 말하던 자리입니다.

### 여태 보낸 우편 모두 지우기 (0.45)

운영자 창 **전체 우편** 단 맨 아래에 있습니다. 확인 글자로 `우편 삭제` 를 적어야 열립니다.

| | 무엇 |
|---|---|
| 지워짐 | 모든 사람의 우편함(받은 것 · 안 받은 것) · **아직 배달을 기다리던 전체 발송** |
| 남음 | 이미 받아서 소지품에 들어간 물건 — 사라지는 것은 편지지뿐입니다 |

> **배달 대기까지 지우는 것이 핵심입니다.** 전체 발송은 '이벤트 통' 에 넣어 두었다가
> 각자 접속할 때 우편함으로 옮겨 줍니다. 우편함만 비우면, 아직 안 들어온 사람이
> 다음에 접속할 때 **똑같은 우편이 다시** 들어옵니다. 지웠는데 도로 생기는 것만큼
> 나쁜 것이 없어서 두 곳을 함께 비웁니다.

### 시트를 읽어 올 문서는 세 곳에서 찾습니다 (0.45 → 0.51)

| 차례 | 어디 | 어떻게 바꾸나 |
|---|---|---|
| **①** | **운영자 창 표 단에서 정한 문서** (0.51) | 주소를 붙여 넣고 저장 — **서버를 다시 안 올려도 됩니다** |
| ② | 환경변수 `SHEET_ID` | Render 설정에서 고치고 재배포 |
| ③ | 저장소 `sheets/SOURCE.txt` | 파일을 고치고 다시 올리기 |

셋 다 없으면 서버가 시작 로그에 그렇다고 적고, 단추를 누르면 **무엇을 해야 하는지**
알려 줍니다(예전에는 "설정되어 있지 않습니다" 한 줄뿐이었습니다).

#### 시트는 **통합문서 한 장**으로 받습니다 (0.52)

```
https://docs.google.com/spreadsheets/d/<문서아이디>/export?format=xlsx
```

0.51 까지는 탭마다 구글의 `gviz` 통로로 CSV 를 받았습니다. 그런데 그 통로는
**스스로 짐작합니다.** 두 번 다른 이유로 막혔습니다:

| 판 | 무엇을 짐작했나 | 어떻게 보였나 |
|---|---|---|
| 0.50 | 제목 줄이 몇 줄인지 | 첫 칸이 `직업 warrior warrior warrior` |
| 0.52 | 열의 자료형 | `classes 시트 2번째 줄: 이름은 비울 수 없습니다` |

두 번째가 특히 고약합니다. `classes` 탭의 `값` 열에는 `용사`·`예` 같은 글자와
`48`·`11` 같은 숫자가 섞여 있는데, 숫자가 더 많으니 구글이 그 열을 숫자로 보고
**글자 칸을 빈칸으로 지워서** 줍니다. 시트에는 멀쩡히 적혀 있는데 서버만 못 봅니다.

> **같은 통로에서 두 번 막히면 그 통로를 고칠 것이 아니라 버립니다.**
> `export?format=xlsx` 는 아무것도 짐작하지 않습니다 — 칸에 적힌 것이 그대로 옵니다.
> 덤으로 요청이 **열 번에서 한 번**으로 줄고, 탭을 반쯤 읽다 마는 상태가 없어집니다.

xlsx 읽기는 `server/xlsxread.js` 에 있습니다. 바깥 라이브러리는 안 씁니다 —
xlsx 는 XML 몇 장을 zip 으로 묶은 것이고, zip 은 node 의 `zlib` 만으로 풉니다
(굽는 쪽 `tools/make-xlsx.js` 와 같은 방식입니다).

#### 왜 운영자 창에서 바꿀 수 있어야 하나 (0.51)

**문서 아이디가 판마다 바뀌고 있었습니다.** 시트를 새로 만들어 올리면 아이디가
달라지는데, 그때마다 저장소를 고치고 다시 배포해야 서버가 새 문서를 봤습니다.
그 사이 서버는 없어진 문서를 두드리며 `401` 만 받았고, 화면에는
"공개했는지 보세요" 만 떠서 **멀쩡한 시트의 공개 설정**을 붙들게 했습니다.
0.45 부터 0.51 까지 **여섯 판 연속**으로 같은 일이 났습니다.

```
  지금 보는 문서
  19yz0jylJE3PcA5A7Py8pnk6focMzJYCdzepM09KpmzM
  저장소의 sheets/SOURCE.txt

  시트 주소  [ https://docs.google.com/spreadsheets/d/…  ]
  [ 주소 저장 ]  [ 원래대로 ]
```

**지금 보고 있는 문서를 맨 위에 적는 것**이 절반입니다 — 아이디가 눈에 보이면
"내 시트가 아니네" 가 곧바로 보입니다. 안 보이면 공개 설정만 몇 번이고 다시 봅니다.

여기서 정한 값이 **환경변수보다 셉니다.** 순서를 뒤집으면 환경변수가 낡았을 때
재배포 말고는 길이 없어져, 이 기능이 있으나 마나가 됩니다.
보관은 계정과 같은 곳(`store` 의 문서 칸)에 하므로 Upstash 를 쓰면 서버가 자다 깨어나도 남습니다.

`401` · `404` 오류 글도 바꿨습니다 — "그 문서가 없어졌거나(새로 만들어 올리면
아이디가 바뀝니다) 공개가 풀렸습니다. 운영자 창 표 단에서 지금 시트 주소를 붙여 넣고
저장해 보세요." `403` 일 때만 공개 설정을 말합니다.

> ⚠ 어느 쪽이든 그 문서는 **"링크가 있는 모든 사용자 — 뷰어"** 로 공개되어 있어야 합니다.
> 공개하고 싶지 않다면 `sheets/SOURCE.txt` 의 마지막 줄을 지우고 환경변수만 쓰세요.

> **애초에 안 바뀌게 하려면** — 같은 문서에 **파일 → 가져오기 → 현재 시트 바꾸기**
> (덮어쓰기로 가져오기)를 쓰세요. 새 문서를 만들지 않으면 아이디가 안 바뀝니다.

### 운영자 창 — 운영자 계정으로 접속했을 때만

서버에 **`ADMIN_KEY`** 가 정해져 있으면, 서버가 켜질 때 **`admin`** 계정을 하나 만들어 둡니다
(비밀번호 기본값 `@2222` · 환경변수 `ADMIN_PW` 로 바꿉니다). 그 아이디로 접속하면
HUD 오른쪽에 **🛡** 버튼이 하나 더 생깁니다.

| 단 | 하는 일 |
|---|---|
| **우편** | **전체 유저**(기본) 또는 **고른 사람에게만**. 아이템을 **장비 · 소모품 · 재료**로 갈라 고르고 개수를 적습니다. 골드·경험치·유효기간(기본 7일)도 함께 |
| **랭킹** | 전체 초기화(= 시즌 넘기기) · 보스 하나만 지우기 · **전체 유저 초기화**(0.40) |
| **표** | 구글 시트를 지금 당장 읽어 반영 |

#### 전체 유저 초기화 — 다음 시즌 시작 (0.40)

랭킹 단 맨 아래에 있습니다. 누르면 **모든 사람이 캐릭터를 갓 만든 상태로** 돌아갑니다.

| | |
|---|---|
| **지워짐** | 레벨 · 소지품 · 장비 · 퀘스트 · 우편함 · 잡은 기록 · 랭킹 표(지난 시즌으로 이동) |
| **남음** | 계정 자체 — 아이디 · 비밀번호 · 이름. **다시 만들 필요가 없습니다** |

- 되돌릴 수 없으므로 **`다음 시즌` 이라고 직접 쳐 넣어야** 단추가 열립니다.
- **접속 중인 사람**에게는 그 자리에서 "다음 시즌이 시작되었습니다" 가 화면을 덮고,
  4초 뒤 접속 화면으로 돌아갑니다.
- **자고 있던 사람**은 다음에 들어올 때 같은 말을 한 줄로 봅니다(계정에 표시를 남겨 둡니다).
- ⚠ 가장 조심한 자리: 알림을 받은 순간 그 브라우저의 **자동 저장을 통째로 끕니다.**
  안 끄면 20초 뒤 자동 저장이 방금 비운 자리에 옛 캐릭터를 도로 써넣어, 접속 중이던
  한 사람만 초기화가 안 되는 사고가 납니다. `/tmp/seasonreset.js` 가 이것까지 확인합니다.

#### 시즌 시작 선물 (0.41)

초기화 단추 **바로 옆**에 있습니다. 한 번 누르면 전 유저에게 시작 꾸러미가 우편으로 갑니다.

| | |
|---|---|
| 들어가는 것 | 회복약 ×20 · 마력석 ×10 · 약초 ×20 · 🪙 5,000 |
| 받는 기한 | 7일 |
| 받는 사람 | **전 유저** — 지금 접속 안 한 사람도 다음에 들어올 때 받습니다 |

무엇이 나가는지 **누르기 전에** 단추 아래에 그대로 적혀 있습니다. 꾸러미의 내용은
`src/ui/AdminPanel.js` 의 `SEASON_GIFT` 한 곳에만 있고, 화면도 그 표를 읽어 보여 줍니다 —
적힌 것과 나가는 것이 갈릴 수 없습니다.

> 갓 만든 캐릭터가 받는 것이라 "앞서 나가게" 가 아니라 **"첫 걸음이 덜 고되게"** 로 짰습니다.
> 다른 내용으로 보내고 싶으면 우편 단에서 직접 고르면 됩니다 — 이 단추는 늘 같은 꾸러미입니다.

**초기화하면서 함께 보낼 수 있습니다 (0.42).** 확인 칸 바로 아래에
**"초기화한 뒤 시즌 시작 선물도 함께 보내기"** 가 있고 **기본으로 켜져 있습니다.**
두 번 눌러야 하면 선물만 잊기 쉬운데, 초기화 직후에는 화면이 덮이고 새로고침이 걸리므로
그때 놓치면 영영 못 보냅니다. 그래서 **화면을 덮기 전에** 선물을 먼저 보내고,
보냈는지 아닌지를 상태 줄에 그대로 적습니다.

**받을 사람 고르기 (0.35)** — 우편 단 맨 위에 **`전체 유저` / `고른 사람에게만`** 두 칸이 있고
**기본은 전체 유저**입니다. `고른 사람에게만` 을 누르면 계정 목록이 펼쳐지고,
검색창으로 걸러 낸 뒤 눌러서 담습니다(`전부` · `비우기` 버튼도 있습니다).
보내기 버튼에 **"3명에게 보내기"** 처럼 몇 명인지가 그대로 적혀서, 전체로 보낼 참인지
몇 명에게 보낼 참인지 누르기 전에 보입니다.

- 한 번에 **200명**까지입니다. 그 이상은 서버가 거절합니다.
- 없는 아이디가 섞여 있으면 나머지는 보내고, **못 찾은 아이디를 돌려줍니다** —
  조용히 빠뜨리면 "보냈는데 안 왔다"가 됩니다.
- 전체로 보낼 때와 고른 사람에게 보낼 때는 서버에서 길이 다릅니다.
  전체는 `world.addEvent`(접속할 때 각자 받아 감), 지정은 `world.sendMail`(계정마다 바로 꽂음)입니다.
- 계정 목록은 `/api/admin/accounts` 로 가져오고, 이 길도 `adminOnly()` 뒤에 있습니다.

**운영자는 기본이 투명입니다.** 창 위의 버튼으로 모습을 보였다 감췄다 할 수 있습니다.
투명한 동안에는 **내 자리를 아예 안 보냅니다** — 남의 화면에서 안 보이는 것이 아니라
남에게 알리지 않는 것이라, 상대 브라우저에도 내가 없습니다. 제 화면에는 희미하게 남습니다
(안 그러면 자기가 어디 있는지 모릅니다). 모습은 흰 갑옷의 **빛의 심판관**입니다 — 얼굴이 없어서
한눈에 사람이 아닌 것으로 보입니다.

> **잠금은 전부 서버에 있습니다.** `ADMIN_KEY` 는 브라우저로 **절대 내려가지 않습니다.**
> 화면이 보내는 것은 제 세션 토큰뿐이고, "이 토큰이 운영자의 것인가"는 서버만 판단합니다
> (`server/server.js` 의 `adminOnly`). 그래서 `src/ui/AdminPanel.js` 를 아무리 뜯어봐도
> 아무 권한이 생기지 않습니다. `ADMIN_KEY` 가 비어 있으면 **운영자 계정 자체를 안 만듭니다.**
>
> ⚠ **공개 서버라면 기본 비밀번호를 반드시 바꾸세요.** `@2222` 는 짧고 문서에 적혀 있습니다.
> `ADMIN_PW` 를 정하고 계정을 지운 뒤 서버를 다시 켜면 새 비밀번호로 만들어집니다.

### 우편은 7일 뒤에 사라집니다

우편에는 유효기간이 있습니다. 아무 말이 없으면 **7일**이고, 보낼 때 날수를 정해 바꿀 수 있습니다
(`0` 을 적으면 안 사라집니다). 받기 전의 우편에는 **"3일 뒤 사라짐"** 처럼 남은 날이 함께 뜹니다.

기한이 지난 우편은 그 사람이 **우편함을 열 때** 조용히 치워집니다. 따로 청소 시계를 두지 않는
이유는, 아무도 안 오는 계정의 우편을 지우려고 서버가 주기적으로 전체를 훑을 이유가 없기 때문입니다.

왜 두느냐 — 우편함은 계정마다 한 문서이고 최대 60통입니다. 이벤트를 몇 번 뿌리고 고룡을
몇 번 잡으면 안 읽은 우편이 쌓여 **새로 온 것이 위쪽에서 밀려납니다.**

### 우편함 · 타임어택 · 이벤트 — 서버가 있을 때만

이 셋은 **서버에 접속해서 할 때만** 뜻이 있습니다. 여럿이 같은 것을 보는 기능이라서요.
혼자 할 때는 조용히 비어 있습니다 — 없는 기능이지 고장이 아닙니다.

**우편함 (HUD ✉ · `M`)**

- 고룡을 함께 눕힌 **몫**과 운영자가 보내는 **이벤트 선물**이 옵니다.
- 안 받은 편지가 있으면 봉투에 숫자가 붙습니다.
- 받기는 서버가 먼저 "받음"으로 바꾼 뒤 소지품에 넣습니다.
  순서를 바꾸면 넣는 도중에 끊겼을 때 같은 편지를 두 번 받게 됩니다.

**타임어택 (HUD 🏆 · `R`)**

- 재는 것은 **계정을 만든 순간부터 그 보스를 처음 눕힌 순간까지**입니다.
  "몇 번 만에 이겼나"가 아니라 "얼마 만에 여기까지 왔나"를 겨루는 판이라,
  레벨을 올리는 속도와 장비를 갖추는 속도가 전부 여기에 들어갑니다.
- **처음 잡은 기록만** 셉니다. 다 키운 캐릭터로 다시 잡아도 기록은 바뀌지 않습니다.
- 탭은 보스마다 하나씩(5·10·15·20단계 · 지하 5층 · 고룡), 각 탭에 **상위 5명**.

**랭킹은 시즌으로 갑니다.** 창 위에 **현재 시즌 / 지난 시즌** 두 단이 있습니다.
운영자가 전체 초기화를 하면 지금 표가 통째로 **지난 시즌으로 옮겨지고** 시즌 번호가 하나 오릅니다 —
지워지는 것이 아니라 옮겨지는 것이라, "내가 1등이었는데"를 나중에도 확인할 수 있습니다.
표 하나만 지우는 것은 시즌을 넘기지 않습니다(잘못 올라간 기록을 손볼 때 씁니다).
- 표 아래에 **내 기록** 줄이 붙습니다 — 5위 밖이어도 `6위 / 12명 · 3시간 12분 ·
  1위와 40분 차이` 처럼 정확한 자리를 알려 줍니다. 5위 안이면 위 표에서
  이미 강조되므로 이 줄은 뜨지 않습니다.
  (그래서 서버는 5위까지만이 아니라 **모든 기록**을 갖고 있고, 화면에만 5명을 보냅니다)

> **걸린 시간은 서버가 잽니다.** 게임 쪽은 "이 보스를 잡았다"만 알리고,
> 시간은 서버가 첫 캐릭터를 만들 때 찍어 둔 시각으로 직접 계산합니다.
> **빠를수록 위**입니다(오름차순 정렬).
>
> 처음에는 게임이 잰 시간을 그대로 받아 적었습니다. 그러면 브라우저 콘솔에
> 한 줄만 치면 1초 기록이 올라가는 표가 됩니다 — 남과 견주는 것이 전부인 표에서
> 그 값은 아무 뜻이 없습니다. "처음 잡은 것만 센다"는 규칙도 같은 이유로
> 서버가 계정에 적어 두고 지킵니다.

**이벤트 우편 보내기 (운영자)**

```bash
ADMIN_KEY=열쇠 node tools/event.js "추석 선물" "즐거운 명절 보내세요!" potion:20 dragon_token:2
SERVER=https://내서버.onrender.com ADMIN_KEY=열쇠 node tools/event.js "점검 보상" "기다려 주셔서 고맙습니다." greater_potion:5
```

- 서버를 켤 때 `ADMIN_KEY` 를 정해 두어야 합니다.
  **비워 두면 발송 경로 자체가 막힙니다** — 열쇠 없이 열려 있으면
  누구든 전 유저에게 아이템을 뿌릴 수 있다는 뜻이라 없느니만 못합니다.
- 계정마다 한 통씩 넣지 않습니다. 한 곳에 적어 두고 각자 접속할 때
  "마지막으로 가져간 시각" 뒤의 것만 가져갑니다.
  그래서 **아직 만들지 않은 계정도** 나중에 접속하면 받아 갑니다.

### 마녀 이올린 — 징표 상점

마을 **서쪽 문 가는 길목**에 있습니다. **골드를 받지 않습니다** — 용의 징표만 받습니다.

| 값 | 받는 것 |
|---|---|
| 징표 ×1 | 보석 하나 (루비 · 사파이어 · 에메랄드 · 토파즈 · 자수정 · 오닉스 · 다이아몬드) |
| 징표 ×2 | **전설 방어구** — 용비늘 성갑 |
| 징표 ×3 | **전설 무기** — 용살자 / 천공궁 / 세계수 지팡이 |

마녀는 **초월 강화**(+10 → +15)도 걸어 줍니다. 규칙은 아래 절에 있습니다.

#### 전설 등급

용의 징표로만 얻습니다. 상점에도 드랍표에도 없습니다.

- 같은 부위 **영웅 장비의 120%** 성능입니다.
- **태어날 때 무작위 옵션 한 줄**을 답니다. 각인과 달리 반드시 붙고, 값도 그 자리에서 굴립니다 —
  같은 용살자라도 사람마다 다른 물건이 됩니다.
- **찍어 둔 스킬의 효과가 두 배**가 됩니다(`skillPower`). 연격 5단계는 연격 10단계처럼 먹힙니다.
- 그 두 배는 **강화로 변하지 않습니다.** +10 을 만들어도 두 배 그대로입니다 —
  두 배는 그 물건의 성질이지 갈고닦아 늘어나는 수치가 아니기 때문입니다.
  (`AffixSystem` 이 이 값만 일부러 강화 배율을 태우지 않고 넘깁니다)

### 보스는 잡은 뒤 1분 뒤에 돌아온다

모든 보스는 쓰러진 뒤 **1분**이 지나야 다시 나타납니다.

> 예전에는 맵을 나갔다 들어오면 보스가 늘 살아 있었습니다. 몬스터 목록을 맵을
> 만들 때마다 새로 뽑았기 때문입니다. 그래서 **문 밖에 한 걸음 나갔다 오는 것만으로**
> 보스를 몇 번이고 잡을 수 있었습니다 — 파밍이라기보다 버그에 가까웠습니다.
> 지금은 죽은 시각을 `state.bossRespawn` 에 적어 두고 맵을 다시 만들 때 그 시각을 봅니다.
> 세이브에도 함께 남으므로 **접속을 끊었다 켜도** 소용이 없습니다.
> (그 사이에 흐른 시간만큼은 저절로 돌아와 있습니다 — 기다린 시간은 인정합니다.)

잡몹은 예전 그대로 10~15초면 돌아옵니다.

### 웨이포인트 (디아블로2 방식)

마을 광장 **한가운데**에 웨이포인트 돌이 하나 있습니다.
**보스를 잡은 맵**이 하나씩 목록에 새겨지고, 고르면 그 땅의 **한가운데**로 곧장 갑니다.
아직 못 연 곳도 "무엇을 잡아야 열리는지"와 함께 회색으로 보여 줍니다.

- 판정은 `src/systems/WaypointSystem.js` 하나에만 있습니다(순수 함수).
- 목적지 좌표는 `maps.json` 의 `waypoint: {x, y}` 입니다. 그 칸이 나무나 바위여도
  `MapSystem.nearestWalkable()` 이 가까운 빈 칸으로 옮겨 주므로 벽에 갇히지 않습니다.
- 해금 목록은 세이브에 남습니다(`SAVE_VERSION 4`). 예전 세이브는 빈 목록으로 시작합니다.

## 화면 배치 (디아블로식)

가운데는 완전히 비웁니다. 상태 표시는 전부 네 귀퉁이로 흩어 놓습니다.

```
 ┌──────────────────────────────────────────┐
 │                                    (!)   │ ← 퀘스트. 다 모으면 반짝인다
 │                                     🏠   │
 │                                     ✦    │
 │                                     🎒   │ ← 오른쪽 세로: 아이콘만
 │              (땅이 다 보인다)         ✉    │
 │                                     🏆   │
 │                                     ⚙    │
 │                                     ?    │ ← 누르면 조작법
 │  ⬤                                      │
 │ HP                        포이노 마을     │
 │ 구슬                       🪙 1,240      │ ← 지금 있는 곳과 골드
 │▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░  62%  │ ← 경험치. 10% 눈금
 └──────────────────────────────────────────┘
```

- **HP 구슬** (왼쪽 아래) — 아래에서 위로 찹니다. 30% 아래로 떨어지면 붉게 뜁니다.
  죽고 사는 값이라 눈이 가장 자주 가는 자리에 둡니다.
- **경험치** (맨 아래) — 가늘고 긴 회색 띠. **10% 마다 눈금**이 있어 몇 칸 남았는지 보입니다.
- **퀘스트** (오른쪽 위) — `!` 아이콘 하나. 다 모으면 **겉이 반짝이고** ✔ 가 붙습니다.
  눌러야 내용이 펼쳐집니다 — 늘 펼쳐 두면 그것도 화면을 가립니다.
- **지금 있는 곳 · 골드** (오른쪽 아래)
- **기능** (오른쪽 세로) — 귀환 · 캐릭터 · 소지품 · 우편 · 랭킹 · 설정 · 조작법.
  아이콘만 두고, 무엇인지는 마우스를 올리면 나옵니다.
- **전투력은 HUD 에서 뺐습니다.** 늘 보고 있을 값이 아니라 장비를 고칠 때 보는 값이라
  **소지품 창과 캐릭터 창**에 있습니다.

> 예전에는 왼쪽 위 카드 하나에 이름·레벨·HP·경험치·전투력·공격·방어·속도·치명·골드·
> 위치·퀘스트·버프를 전부 몰아 두었습니다. 그 카드가 화면 왼쪽을 통째로 덮어서
> 정작 걸어 다니는 땅이 안 보였습니다.
>
> HUD 자체는 클릭을 통과시키고 실제 버튼만 클릭을 받습니다 —
> 그래야 상태 표시 뒤의 땅을 눌러 이동할 수 있습니다.

## 성장과 편의 기능

**단축키 1~4** — 화면 아래 칸에 소모품을 올려 두고 숫자키로 씁니다.
소지품에서 소모품을 고르면 "단축키 지정" 버튼이 나옵니다(우클릭으로 비움).
**필드에서만** 직접 씁니다(쿨타임 0.4초).

**전투 중 회복약은 자동입니다.** HP가 기준선 아래로 내려가면 알아서 마십니다.
기준선은 설정에서 **50~90%** 사이로 바꿀 수 있고 기본값은 70%, 간격은 **2초**입니다.
어떤 약을 마실지는 **단축키 칸 순서**로 정해집니다 — 1번 칸에 올려 둔 약부터 씁니다.
회복량이 큰 것부터 쓰면 아껴 두려던 비싼 약이 먼저 없어져 버립니다.

> 왜 자동인가: 예전에는 전투 중에 물약을 누르면 그 시점의 HP로 남은 전투를 다시
> 계산했습니다. 그런데 **이미 쓰러진 뒤에 눌러도** 계산이 이어져 진 전투가 되살아났습니다.
> 지금은 회복이 `CombatSystem` 안에서만 일어나므로 그런 틈이 없습니다.
> 마시는 것은 차례를 쓰지 않습니다(여러 마리에게 둘러싸였을 때 마실수록 더 맞는 악순환을 막습니다).

### 기세 — 같은 상대라도 판마다 다르다

전투를 시작할 때 상대의 **체력과 공격력이 ±35% 안에서 흔들립니다.**
크게 치우친 판은 전투 기록의 첫 줄에 뜹니다.

```
슬라임이(가) 나타났다!
슬라임은(는) 지쳐 보인다 — 기세 -27%
```

> **왜 넣었나.** 전투는 순수한 계산 경주여서, 능력치가 조금만 넘으면 100%,
> 조금만 모자라면 0% 였습니다. 그 사이가 없으니 "다섯 번 도전해서 한 번 이기는 보스"
> 같은 자리를 아예 만들 수가 없었습니다. 상대의 컨디션이 판마다 다르면
> 아슬아슬한 싸움이 생기고, 졌던 보스에게 다시 붙어 볼 이유가 생깁니다.

seed 로 굴리므로 같은 전투를 다시 계산해도 같은 값이 나옵니다(재현 가능).
폭은 `formulas.js` 의 `MONSTER_MOOD`, 기록에 적는 기준은 `MONSTER_MOOD_SHOW` 입니다.

### 구간 — 보스가 문을 지킨다

동쪽 들판 스무 단계는 **네 구간**으로 나뉩니다. 구간과 구간 사이에는 보스가 서 있고,
**그 보스를 눕히고 그 퀘스트를 마을에 보고해야** 다음 구간의 문이 열립니다.

| 구간 | 단계 | 지키는 보스 | 열쇠가 되는 퀘스트 |
|---|---|---|---|
| 1구간 | 1~5 | 악마 정찰대장 | 직업 시험 |
| 2구간 | 6~10 | 악마 장군 발가르 | 발가르 |
| 3구간 | 11~15 | 강화된 악마 정찰대장 | 되살아난 대장 |
| 4구간 | 16~20 | 강화된 악마 장군 발가르 | — (여기가 끝) |

**20단계에는 동쪽 문이 없습니다.** 예전에는 20단계 오른쪽 끝이 마을로 이어져 있어서
동쪽 들판이 고리처럼 돌았고, "끝에 다다랐다"는 느낌이 없었습니다.
이제 20단계는 막다른 땅이고, 돌아올 때는 귀환이나 웨이포인트를 씁니다.

**새 구간의 첫 땅은 방금 잡은 보스보다 셉니다.**

```
 5단계 보스   855  →  6단계 · 붉은 황야     꼬마 악마 1,391 · 해골 병사 2,149
10단계 보스 5,440  → 11단계 · 되살아난 들판  강화된 슬라임 15,906
15단계 보스 31,672 → 16단계 · 피에 젖은 황야 강화된 꼬마 악마 62,417
```

예전에는 문을 넘자마자 난이도가 푹 꺼졌습니다 — 죽을 힘을 다해 보스를 눕히고 나면
그 다음 땅의 잡몹이 보스의 절반도 안 되었습니다. 이제 문을 넘는 것 자체가 승급입니다.
검사는 `node tools/zone-power.js`, 배율 계산은 `node tools/zone-solve.js` 가 합니다.

동시에 **보스는 언제나 자기 구간에서 가장 셉니다** — 구간 안에서 계속 세지다가
마지막에 보스가 그 위에 서 있고, 그 문을 넘으면 다시 한 칸 올라섭니다.

### 단계 사다리 — 뒤 땅이 앞 땅보다 쉬워지지 않는다 (0.35)

예전에는 **6단계 몬스터가 5단계보다 레벨이 낮았습니다.** 그리고 같은 장비로 다음 땅에
가면 오히려 승률이 올랐습니다. 사람이 겪는 것으로 옮기면 "고생해서 보스를 넘었는데
다음 땅이 더 만만하다" 였고, 그러면 앞으로 나아갈 이유가 사라집니다.

두 가지를 고쳤습니다.

**① 레벨이 뒤로 가지 않게 — 몬스터 표와 배치를 손봤다.**
슬라임 1 · 박쥐 3 · 늑대 6 · 버섯 9 · 꼬마 악마 13 · 해골 병사 17 · 악마 병사 21 로
사다리를 다시 깔고, **한 땅 안의 두 몬스터가 4레벨 넘게 벌어지지 않게** 배치했습니다.
예전에는 해골(17)과 악마 병사(24)가 한 땅에 같이 있어 일곱 칸이 벌어졌습니다.

7단계는 **해골만** 둡니다. 여기서 악마 병사를 미리 꺼내면 6→7 에서 승률이
95% 에서 10% 로 떨어져 사다리가 아니라 절벽이 됩니다.

**② 배율을 승률로 역산했다 — `tools/stage-solve.js`.**
단계마다 **거기 서 있을 법한 몸**(레벨·강화·장비 단계)을 세워 두고, 그 몸이
그 땅의 가장 센 잡몹을 상대로 목표 승률을 내도록 맵 배율을 이분 탐색으로 찾습니다.

| 구간 안 자리 | 첫째 | 둘째 | 셋째 | 넷째 | 마지막(보스가 있는 땅) |
|---|---|---|---|---|---|
| 목표 승률 | 88% | 82% | 76% | 70% | **64%** |

- **한 구간 안에서는 강화 수치를 올리지 않습니다.** 구간 중간에 +9 → +10 을 두었더니
  그 자리에서 승률이 75% 에서 11% 로 떨어졌습니다. 구간 안에서 달라지는 것은 레벨뿐입니다.
- **1~3단계는 손대지 않습니다.** 게임을 배우는 자리이고, 배율을 올리면 경험치·골드까지
  함께 올라 초반 성장 속도가 통째로 달라집니다.
- **마지막 땅도 64% 로 둡니다.** 예전에는 50% 였는데, 그러면 그 땅 보스의 목표(40%·30%·20%)
  와 사이가 좁아 "보스가 제 땅의 잡몹보다 약한" 상태를 피할 수 없었습니다.
- 배율은 **몬스터가 같을 때만** 뒤로 못 갑니다. 더 센 놈이 새로 나오는 땅은 배율이
  낮아져도 실제로는 더 어렵습니다(8단계에 악마 병사가 처음 나옵니다).

**세 도구가 각각 다른 각도에서 봅니다.**

| 도구 | 무엇을 재나 |
|---|---|
| `node tools/stage-solve.js [--write]` | 목표 승률에 닿는 맵 배율을 역산 (`--write` 는 `tools/gen-maps.js` 를 고침) |
| `node tools/stage-curve.js` | **장비를 고정한 몸**으로 걸어갔을 때 뒤 땅이 더 쉬워지는 곳이 없는지 |
| `node tools/stage-color.js` | 이름표 **색**이 거짓말을 하지 않는지 — 색과 **실제 승률**을 나란히 잽니다 |
| `node tools/dungeon-solve.js --rate [--write]` | 지하감옥 층 배율을 **승률로** 역산 (0.36) |

### 얕은 땅(1~4단계)의 고비는 배율로 만들지 않는다 (0.36)

저렙 구간에도 약간의 고비가 있어야 합니다. 1~3단계가 100%·100%·100% 이면 전투가
볼거리로만 남고, 물약도 장비도 쓸 이유가 없어 4단계의 첫 고비가 갑자기 옵니다.

그런데 그 고비를 **맵 배율로 만들면 안 됩니다.** 배율은 경험치·골드도 같은 배수로
함께 올리기 때문입니다(`main.js` 의 `exp: baseDef.exp * power`).

> 실제로 한 번 그렇게 풀어 봤습니다. 1단계를 95% 로 두려면 배율이 **1.327 → 5.163** 이
> 되어야 했고, 그러면 슬라임 한 마리가 9exp 에서 **46exp** 가 됩니다.
> 첫 들판을 한 바퀴 도는 것만으로 **Lv.9** — 4단계를 걷는 몸입니다.
> 고비를 만들려다 2·3단계를 통째로 공짜로 만드는 셈입니다.

그래서 얕은 땅의 고비는 **몬스터 자신의 능력치**로 만듭니다.

```bash
node tools/balance.js --trash --solve --n 60    # 1·2·3단계 줄이 여기 있다
```

경험치·골드는 표에 적힌 그대로 남으므로 초반 성장 속도가 흔들리지 않습니다.
목표는 95% → 92% → 88% 로, 스무 판에 한 번 지는 정도입니다.

⚠ **늑대는 3단계와 4단계에 함께 삽니다.** 3단계 고비를 만들려고 늑대를 세게 하면
4단계가 같이 무너집니다(실제로 82% 에서 12% 가 되었습니다). 몬스터 능력치를 고친 뒤에는
반드시 `node tools/stage-solve.js --write` 로 그 몬스터가 사는 **모든 땅**을 다시 풉니다.

> ⚠ 배율을 바꾸면 그 맵의 **보스도 함께 세집니다.** `stage-solve --write` → `npm run maps`
> 뒤에는 반드시 `node tools/balance.js --solve --hp-only` 로 보스를 다시 잡아야 합니다.

### 단계 보스는 어느 정도로 세게 맞춰 두었나

| 단계 | 기준이 되는 몸 | 목표 승률 |
|---|---|---|
| 5단계 · 악마 정찰대장 | Lv.12 · +2 · 여섯 점 | **50%** |
| 10단계 · 발가르 | **Lv.14 · +7 · 고급(매직) 세 점** | **40%** |
| 15단계 · 강화된 정찰대장 | **Lv.20 · +7 · 희귀 여섯 점** | **30%** |
| 20단계 · 강화된 발가르 | **Lv.27 · +7 · 룬 한 벌** | **20%** |
| 지하감옥 5층 · 감옥의 주인 | Lv.50 · +10 · 룬 한 벌 | **30%** |

> **굵게 적은 셋은 0.50 에서 바뀐 자리입니다.** 예전에는 10단계를 Lv.24 · +5 ·
> **여덟 점**으로, 15단계를 Lv.30 · 룬 한 벌로 상상하고 있었습니다.
> 그런데 실제로 그 문 앞에 서는 사람은 훨씬 가벼운 몸이었습니다.
> **재는 사람이 틀리면 잰 값은 전부 틀립니다** — 이 게임에서 몇 번이나 반복된 실수입니다
> (1단계를 Lv.3 으로 재던 일, 강화 배율을 두 곳에 적어 두던 일).

기준이 되는 몸은 `tools/stage-solve.js` 의 그 구간 **마지막 단계** 몸과 같습니다.
어긋나게 두면 보스가 제 땅의 잡몹보다 약해지는 일이 생깁니다 — 실제로 한 번 그랬습니다.

#### 보스는 제 땅의 잡몹보다 세다 (0.49)

규칙 하나를 못 박고 자를 만들었습니다 — **어떤 땅의 보스는 그 땅에 서는 잡몹
누구보다도 체력과 공격력이 높아야 한다.**

```
node tools/boss-check.js
  ✓ 모든 보스가 제 땅의 잡몹보다 체력·공격력이 높습니다.
```

눈으로는 잘 안 보입니다. 능력치는 `monsters` 에, 누가 어느 땅에 서는지는 `maps` 에
있어서 두 표를 나란히 놓고 봐야 알 수 있기 때문입니다. 실제로 두 자리가 어긋나 있었습니다:

| 땅 | 보스 체력 | 같은 땅 잡몹 체력 | 고친 값 |
|---|---|---|---|
| 5단계 | 악마 정찰대장 103 | 꼬마 악마 **118** | → **150** |
| 10단계 | 발가르 232 | 악마 병사 **260** | → **464** |

맵 배율(field_10 은 ×9.521)은 보스에게도 잡몹에게도 똑같이 걸리므로,
표에서 뒤집힌 순서는 **게임에서도 그대로 뒤집혀 있습니다.**
10단계에서 발가르는 2209, 옆의 악마 병사는 2475 였습니다.

#### 몸 견주기 — 왜 0% 인지 눈으로 (0.50)

`node tools/balance.js` 는 이제 승률 표 아래에 **몸을 나란히** 적습니다.

```
  몸 견주기 — 왼쪽이 사람, 오른쪽이 그 땅에 선 상대
  10단계 보스 · 발가르     hp 435 · atk 129 · def 81     hp 4418 · atk 904 · def 524
  15단계 보스 · 정찰대장   hp 977 · atk 228 · def 224    hp 24051 · atk 2214 · def 1059
  20단계 보스 · 발가르     hp 2434 · atk 366 · def 512   hp 67635 · atk 4739 · def 2370
```

승률만 보면 "0%" 가 왜 0% 인지 알 수가 없습니다. 몸이 나란히 있으면
**도구가 틀렸는지 표가 틀렸는지**가 한눈에 보입니다.
0.49 에서 도구와 사람의 말이 정반대였는데, 이 줄이 있었으면 바로 알았을 것입니다.

#### 사다리가 상상한 사람보다 실제 사람이 가볍습니다 (0.50 에서 드러남)

맵 배율(`maps.json` 의 `power`)은 **"그쯤이면 갖췄겠다" 싶은 몸**에 맞춰 풀어 두었습니다.
그 몸을 실제와 맞추고 다시 풀어 보면 배율이 이만큼 내려가야 합니다:

| 단계 | 지금 배율 | 실제 몸으로 풀면 |
|---|---|---|
| 10단계 | 9.521 | **2.78** |
| 15단계 | 4.814 | **1.04** |
| 20단계 | 9.114 | **2.78** |

`node tools/stage-solve.js` 가 이 값을 내놓습니다(`--write` 를 붙이면 고칩니다).

> ⚠ **아직 안 고쳤습니다.** 배율은 **경험치·골드도 같은 배수로** 올립니다
> (`main.js` 의 `exp: baseDef.exp * power`). 9.5 → 2.8 로 내리면 그 땅에서 받는
> 경험치가 **3분의 1**이 되어 레벨이 오르는 속도가 통째로 바뀝니다.
> 난이도만 고치려던 일이 성장 곡선을 고치는 일이 되므로, 함께 정하고 나서 손댑니다.

> ⚠ **10단계는 이제 많이 어렵습니다.** 체력을 두 배로 올리면 승률이 36% → 4% 입니다.
> 체력은 이 게임에서 가장 세게 먹히는 값이라, 공격력·방어력을 같이 깎아도
> 13% 언저리까지밖에 못 돌아옵니다. 너무 세다 싶으면 시트에서 발가르 hp 를
> 348(1.5배) 로 내려 보세요 — 그 자리가 약 18% 입니다.

이 표는 눈대중이 아닙니다. `node tools/balance.js` 가 게임의 진짜 전투 계산기를 돌려
세 직업 × 200판씩 재고, `--solve` 를 붙이면 목표에 닿는 능력치를 거꾸로 찾아 줍니다.
`--hp-only` 를 붙이면 **HP 만** 건드립니다 — 공격력까지 함께 줄이면 보스가 제 땅의
잡몹보다 약해집니다(`k^0.55` 로 공격이 깎여 실제로 그렇게 되었습니다).
자세한 사용법은 `SHEETS.md` 에 있습니다.

### 마법 피해 — 지능이 값을 하게 (0.37)

예전에는 몬스터의 공격이 **물리 아니면 마법**, 둘 중 하나였습니다. 그런데 필드에
나오는 놈들은 거의 다 물리라서, **지능의 '받는 마법 피해 감소' 가 통째로 죽은 값**이었습니다.
지능을 올려도 그 자리에서는 아무 일도 일어나지 않았습니다.

이제 땅마다 **마법이 섞이는 비율**이 있습니다.

| 어디 | 마법으로 들어오는 몫 |
|---|---|
| 1~10단계 | 0% |
| 11~15단계 | **10%** |
| 16~20단계 | **20%** |
| 15·20단계 보스 | **30%** |
| 지하감옥 · 고룡의 둥지 | **50%** |

섞인 만큼만 걸립니다.

```
맞은 값 = 물리 몫 + 마법 몫 × (1 − 받는 마법 피해 감소)
        = 그냥 맞을 값 × (1 − 섞인 비율 × 감소)
```

20%가 섞인 땅에서 마법 피해 감소 50%를 갖추면 **10%**가 깎입니다.
통째로 마법인 상대(고룡·지하의 망령)는 예전 그대로 절반이 깎입니다.

- **10단계까지는 0%로 둡니다.** 지능을 아직 올릴 수 없는 자리에 마법을 섞으면
  막을 방법이 없는 피해가 됩니다. 5·10단계 보스도 그래서 그대로입니다.
- 값은 `maps.json` 의 `magicPart`(보스는 `bossMagicPart`)에 있고,
  `tools/gen-maps.js` 의 `magicPartOf()` 가 정합니다.

**마법사는 주는 피해를 전부 마법으로 바꿉니다.** 그러면서 **1.1배**를 곱합니다
(`classes` 탭의 **마법 전환 배율**). 마법사가 세 직업 가운데 뒤처져 있었는데,
이 값으로 20단계 보스 16% → 23%, 지하감옥 주인 34% → 45% 가 되었습니다.

### 스탯 — 힘 / 민첩 / 지능 (레벨이 알아서 올려 준다)

**포인트로 찍지 않습니다.** 레벨이 오르면 직업이 알아서 올려 줍니다.
직업마다 **잘 자라는 차례**가 있고, 그 차례대로 몫을 **3 : 2 : 1** 로 나눠 갖습니다.

| 직업 | 1등 (몫 3) | 2등 (몫 2) | 3등 (몫 1) | 50레벨에서 (운 없이) |
|---|---|---|---|---|
| **용사** | 힘 | 민첩 | 지능 | 45 / 30 / 15 |
| **사냥꾼** | 민첩 | 지능 | 힘 | 15 / 45 / 30 |
| **마법사** | 지능 | 힘 | 민첩 | 30 / 15 / 45 |

한 레벨에 나눠 주는 총량은 **11/6점(≈1.83)** 이고, 점수를 줄 때마다 **20% 확률로 한 점을 더**
얹습니다. 세 스탯 모두 같은 확률이라 **운이 비율을 흔들지 않습니다** — 규칙이 3:2:1 을 지키고,
운은 그 위에 얹히기만 합니다. 그래서 같은 레벨의 같은 직업이라도 사람마다 총점이 조금씩
다릅니다(50레벨이면 평균 108점쯤).

> ### 0.42 에서 고쳤습니다 — 다 키우면 3:2:1 이 아니었습니다
>
> `classes.json` 의 1·2·3 을 **"몇 레벨마다 한 점"** 으로 읽고 있었습니다.
> 그러면 1/1 : 1/2 : 1/3 이라 **6 : 3 : 2** 가 됩니다 — 50레벨 용사가
> 힘 50 · 민첩 25 · 지능 16 이었습니다. 표에는 1·2·3 이라고 적어 두고
> 다 키운 캐릭터를 보면 안 맞으니, 사람이 "왜 이러지" 할 수밖에 없었습니다.
>
> 지금은 같은 숫자를 **차례**(1등·2등·3등)로 읽고 몫을 3:2:1 로 나눕니다.
> 한 레벨에 나눠 주는 총량은 예전과 같아서(11/6점) **다 키운 캐릭터의 총점은 그대로**이고,
> 갈리는 몫만 제대로 3:2:1 이 됩니다. 소수점은 버리지 않고 쌓았다가 제때 한 점이 됩니다
> (`floor(레벨 × 몫) − floor((레벨−1) × 몫)` — 세이브에 따로 적어 둘 것이 없습니다).
>
> **이미 키워 둔 캐릭터의 스탯은 깎지 않습니다.** 옛 규칙으로 자란 값이 새 최소치보다
> 높으면 그대로 둡니다 — 접속했더니 스탯이 줄어 있는 것이 가장 나쁩니다.
> 앞으로 자라는 몫만 새 규칙을 따릅니다.
>
> `node tools/stat-growth.js` 가 1레벨부터 만렙까지 200명을 실제로 키워 보고
> 비율이 지켜지는지 잽니다(회귀에 들어 있습니다).

| 스탯 | 1점당 | 어떤 캐릭터가 되는가 |
|---|---|---|
| **힘** | 공격력 +3, 방어력 +4 | 때리고 버틴다 |
| **민첩** | **공격력 +1**, 속도 +1.2, 치명타 피해 +0.8%, 연속 공격 +0.4% | 먼저 움직이고 더 아프게 |
| **지능** | **체력 +5**, **공격력 +1**, 마법 피해 +1%, 치명타 확률 +0.25%, 받는 마법 피해 -0.5% | 마법으로 싸운다 |

세 스탯 모두 공격력을 올려 줍니다 — 힘이 가장 크고(+3), 민첩과 지능은 +1 입니다.
그래서 자기 직업이 기대지 않는 스탯이 올라도 아주 헛되지는 않습니다.

> **예전에는 이 셋을 포인트로 찍었습니다.** 그런데 자기 직업이 기대는 쪽에 몰아 주는 것
> 말고는 답이 없어서, 실제로는 선택이 아니라 절차였습니다. 이제 이 셋은 직업이 알아서
> 자라고, 사람이 고르는 것은 아래 여섯 갈래뿐입니다. 창에도 `0/80` 같은 최대치가 없습니다 —
> 위가 없으니까요.

수치는 `src/data/stats.json` 에 있습니다.

여섯 갈래에 다섯 칸씩 서른 칸이므로 다 채울 수 없고, **무엇을 포기할 것인가가 곧 빌드**입니다.

### 치명타 확률은 85%에서 멈추고, 넘친 몫은 피해로 바뀐다

확률이 100%가 되면 "치명타"라는 말이 뜻을 잃고, 그 위로 올리는 장비가 죽은 옵션이 됩니다.
그래서 **85%가 천장**이고, 넘긴 몫은 버리지 않고 치명타 피해로 바꿉니다 —
**1%p 넘길 때마다 치명타 피해 +10%p**. 확률을 끝까지 올린 사람의 다음 한 장도 값이 있습니다.
(`formulas.js` 의 `CRIT_CAP` · `CRIT_OVERFLOW_TO_DMG`)

### 스킬 — 자유 배분 (3레벨마다 1포인트)

**단계도 선행 조건도 없습니다.** 가진 포인트로 아무거나, 아무 순서로나 찍습니다.
Lv.50 까지 16포인트뿐이고 직업마다 8종·합계 37단계이므로,
**무엇을 포기할 것인가가 곧 빌드**입니다.

#### 용사 — 방어를 공격으로 바꾼다

| 스킬 | 최대 | 효과 |
|---|---|---|
| 가시 갑옷 | 5 | 맞는 **그 순간** 방어력의 10% 를 그대로 되돌려 준다 (치명타는 붙지 않는다) |
| 불굴의 심장 | 4 | 최대 HP +25% — **네 단계면 정확히 두 배** |
| 전투 본능 | 5 | **방어력의 8% 가 공격력에 더해진다** |
| 강철 의지 / 철벽 | 5 / 5 | 받는 피해 -4% / 방어력 +8% |
| 광폭화 / 연격 | 3 / 5 | 받는 피해 -4% / 2회 공격 +6% |
| 처형자 | 3 | 치명타 피해 +12%, 관통 +5% |

> **가시 갑옷은 내 차례를 기다리지 않습니다.** 맞은 그 판정 안에서 상대 HP 가 깎이고,
> 전투 화면에도 그 자리에서 숫자가 튀어오릅니다(로그에는 `가시 갑옷 150`).
> 예전에는 계산은 제때 됐는데 **화면이 다음 내 공격까지 갱신되지 않아** 늦게 들어가는 것처럼
> 보였습니다. 그리고 **치명타 배율은 여기에 붙지 않습니다** — 내가 때린 것이 아니라
> 상대가 가시에 스스로 찔린 것이라, 값은 언제나 `방어력 × 비율` 하나입니다.

#### 사냥꾼 — 먼저 쏘고, 자주 쏘고, 맞지 않는다

| 스킬 | 최대 | 효과 |
|---|---|---|
| 속사 / 매의 눈 | 5 / 5 | 2회 공격 +7% / 치명타 확률 +2.5% |
| 가벼운 발 / 바람의 걸음 | 5 / 5 | 받는 피해 -3.5% / 회피 +3% |
| 사냥꾼의 표식 / 죽음의 일격 | 5 / 5 | 관통 +5% / 치명타 피해 **+20%** (0.41 에서 30% → 20%) |
| **예측 공격** (0.41) | 3 | **선제 공격 피해 +70%** — 세 포인트면 +210%, 세 배가 조금 넘는다 |
| 사냥의 집중 | 3 | HP 50% 이하일 때 주는 피해 +14% |

**전투 화면이 예측 공격을 알려 줍니다 (0.42).** 붙기 전에 나가는 두 발은
로그에 `(선제 사격! · 예측 +210%)` 로 적히고, 피해 숫자는 **초록 화살 색에 🎯** 를 달고
튀어오릅니다. 스킬에 세 점을 부었는데 화면이 아무 말도 안 하면 부은 값이 안 보입니다.
스킬을 안 찍었으면 `예측 +` 는 붙지 않습니다 — 없는 것을 있다고 하지 않습니다.

> **0.41 에서 '연발 사격'이 '예측 공격'으로 바뀌었습니다.**
> 예전에는 붙기 전에 쏘는 화살을 2발 → 5발까지 **늘렸습니다.** 화살이 늘면 전투가
> 시작되기도 전에 잡몹이 눕는 일이 잦아, 사냥꾼만 '전투 화면을 안 보는 직업' 이 되었습니다.
> 지금은 화살 수는 2발 그대로 두고 **한 발 한 발을 세게** 합니다 — 같은 사냥꾼다움을
> 지키면서, 상대가 셀수록 값이 커지는 쪽으로 옮긴 것입니다.
> 이미 찍어 둔 연발 사격 포인트는 **접속할 때 자동으로 돌아옵니다.**
>
> 죽음의 일격은 치명타 피해 30% → **20%** 로 내렸습니다. 다섯 단계에 +150% 는
> 다른 어떤 스킬보다도 컸고, 사냥꾼이 15단계 보스에서 49% 를 내는 가장 큰 이유였습니다.

### 전투력 — 붙기 전에 아는 법

HUD와 캐릭터 창에 **전투력** 수치가 하나 있습니다.

필드 몬스터의 머리 위에는 **이름과 레벨**이 뜨고, 그 색이 곧 경고입니다.

| 내 전투력 대비 | 색 | 뜻 | 대략 이길 확률 |
|---|---|---|---|
| ~0.90배 | 흐린 회색 | 한 수 아래 | 95% 이상 |

| ~2.05배 | 흰색 | 비슷 | 60~80% |
| ~2.45배 | 주황 | 버거움 | 35~60% |

`node tools/stage-color.js` 가 스무 단계 전부에서 **색과 실제 승률을 나란히 재어** 확인합니다.

> **0.36 에서 이 표를 통째로 다시 잡았습니다.** 예전 경계는 "알맞은 캐릭터가 0.45~0.60"
> 이라는 전제로 잡혀 있었는데, 그 전제가 오래전에 무너져 있었습니다. 실제로 재 보니
> **스무 단계 가운데 열아홉이 배수 1.2~1.9 에 몰려 전부 주황(버거움)** 으로 떴습니다.
> 그런데 그 싸움들의 실제 승률은 **64~97%** 였습니다 — 사람이 이길 수 있는 땅을
> 한결같이 "버거움"으로 보고 있었던 것입니다. 색이 늘 같은 말을 하면 색이 없는 것과 같습니다.
>
> 지금은 스무 자리 가운데 열여섯이 정확히 맞고, 어긋나는 넷도 **한 칸 차이**입니다.
> 전투력은 직업 궁합도 물약도 스킬도 모르는 잣대라 잣대 하나로는 여기까지가 한계입니다
> (같은 배수 1.49 가 78% 이기도 하고 91% 이기도 합니다).

**강화** — 마을 **대장간에서만** 할 수 있습니다(소지품 창에서는 안내만 나옵니다).
+5까지는 넉넉하고 그 위부터 어려워집니다: `97 / 94 / 90 / 86 / 82 / 68 / 58 / 48 / 38 / 28 %`
**+7·+8·+9 에서 무작위 옵션이 하나씩** 붙고, **+10 에서 보석 홈이 하나** 열립니다.
두 번째 홈은 강화로는 열리지 않습니다 — 지하감옥에서만 나오는 **홈 뚫는 송곳**이 필요합니다(아래).

#### 등급이 낮으면 덜 오릅니다

한 단계 올릴 때 얼마나 오르는지는 **장비 등급**이 정합니다. 영웅을 100 이라 할 때:

| 등급 | 상대치 | +1당 실제 증가 | +9 에서 |
|---|---|---|---|
| **영웅 · 전설** | 100 | 16% | ×2.44 |
| **희귀** | 80 | 12.8% | ×2.15 |
| **일반 · 고급(녹템)** | 65 | 10.4% | ×1.94 |

> 예전에는 모든 등급이 똑같이 16% 였습니다. 그래서 흔한 일반 장비를 +9까지 올리면
> 구하기 어려운 영웅 장비를 그대로 따라잡았고, **좋은 장비를 찾을 이유가 사라졌습니다.**
> 이제 같은 +9라도 등급이 낮으면 덜 오릅니다.

수치는 `formulas.js` 의 `ENHANCE_BONUS_BY_RARITY` 한 곳에 있습니다.

아이템은 숫자 칸이 여럿이라 눈으로는 역전을 알 수 없습니다 —
실제로 룬 장비 몇 개가 그 앞 단계보다 약한 채로 오래 있었습니다.

### 각인 장비 (주울 때 열에 하나)

바닥에서 줍거나 상점에서 산 장비에 **열에 하나꼴로** 덤 한 줄이 붙습니다.
목록에서 이름 앞에 **✦** 가 붙어 한눈에 보입니다.

**수치는 등급이 정합니다 (0.38).**

| 등급 | 각인 수치 |
|---|---|
| 일반 | +3~5 |
| 고급 | +4~7 |
| 희귀 | +5~10 |
| 영웅 | +10~15 |
| **전설** | **+20~30** |

비율 옵션이면 퍼센트(+20~30%), 힘·민첩·지능이면 점수(+20~30점)로 읽습니다.

> **예전에는 등급을 안 봤습니다.** 그 부위 옵션 통의 한가운데를 썼기 때문에,
> 전설 장비의 각인이 일반 장비와 똑같은 7.5% 였습니다. 좋은 물건을 주울 이유가
> 각인 쪽에는 없었던 셈입니다. 이제 등급이 높을수록 각인도 셉니다.

#### 초월 각인 — 각인 열에 하나 (0.38)

각인이 붙은 물건 가운데 **열에 하나**는 **초월**로 태어납니다.
이름 앞에 **✦✦** 가 붙고 **붉은 글씨**로 뜹니다.

초월이 붙은 물건은 **그 물건에 붙는 모든 값이 최대치**입니다.

| | 보통 각인 | **초월 각인** |
|---|---|---|
| 각인 수치 | 그 등급 범위에서 굴린다 | **범위의 최대치로 굳는다** |
| +7·+8·+9 옵션 | 통에서 굴린다 | **전부 최대치** |
| 다시 굴리기(리롤) | 다시 굴린다 | **최대치로만 나온다** |

그래서 초월이 붙은 전설 무기는 "언젠가 잘 굴러 주기를 기다리는" 물건이 아니라
**처음부터 끝난 물건**입니다. 리롤 비용도 아낍니다.

**마법사에게 값이 붙는 자리입니다.** 마법사 패시브는 각인 확률을 지능에 따라
올려 줍니다(`각인 확률 추가`). 각인이 자주 붙는다는 것은 곧 **초월을 노릴 수 있다**는
뜻이라, "마법사로 장비를 줍는다" 는 일에 이유가 생깁니다.

#### 어디서 알려 주나 (0.39)

초월은 **백에 하나**입니다(각인 열에 하나 × 그 안에서 열에 하나). 가방을 열기 전에
지나가 버리면 있었는지도 모릅니다. 그래서 세 곳에서 따로 말해 줍니다.

| 어디 | 무엇이 보이나 |
|---|---|
| 알림(토스트) | 보통 각인은 연보라 한 줄, **초월은 붉은 띠에 조금 더 오래** 머뭅니다 |
| 전투 결과 카드 | 전리품 아래 `✦✦ 초월 각인 — 화염검 · 공격력 +10% (최대치)` 한 줄 |
| 장비 칸 · 상점 판매 목록 | 이름 앞 **✦✦** 와 붉은 글씨 — 모르고 파는 일을 막습니다 |

> 전리품 줄에 섞어 적지 않고 **따로** 세우는 이유가 있습니다. 같은 물건이 둘 떨어졌을 때
> 어느 쪽에 각인이 붙었는지는 "화염검 ×2" 한 줄로 말할 수 없기 때문입니다.

#### 숫자를 고치는 곳 — 구글 시트 `engrave` 탭 (0.39)

`src/data/affixes.json` 의 `"각인"` 이 원본이고, **구글 시트의 `engrave` 탭**에서도
그대로 고칠 수 있습니다(`sheets/engrave.csv`).

| 등급 | 이름 | 최소 | 최대 | 붙을 확률 % | 초월 확률 % |
|---|---|---|---|---|---|
| common | 일반 | 3 | 5 | 10 | 10 |
| legendary | 전설 | 20 | 30 | 10 | 10 |

확률도 **등급마다 따로** 줄 수 있습니다 — 전설만 초월이 잘 뜨게 하거나, 일반은
아예 안 붙게 하는 식입니다. 비워 두면 표 전체의 기본값(`확률` · `초월확률`)을 씁니다.

```jsonc
"각인": {
  "확률": 0.1,
  "초월확률": 0.1,
  // [ 최소, 최대, 붙을확률, 초월확률 ] — 뒤 둘은 없어도 된다
  "등급": { "common": [3, 5, 0.1, 0.1], "legendary": [20, 30, 0.1, 0.1] }
}
```

### 무작위 옵션 (+7 ~ +9)

> **흡혈은 무기와 허리띠에서만 나옵니다.** 예전에는 무기·반지·목걸이·허리띠에 다 붙고
> 보석으로도 박을 수 있어서, 한 벌을 갖추면 흡혈이 **60%를 넘었습니다.** 그러면 때릴 때마다
> 맞은 것보다 더 많이 차올라 아예 죽지 않는 캐릭터가 됩니다 — 레벨 40 용사가 룬 +10 한 벌로
> 고룡을 혼자 잡고 체력이 87% 아래로 내려가지 않았습니다. 지금은 두 자리에서만,
> 5~8% 로만 나옵니다(다 갖춰도 최대 76%). 스킬의 흡혈은 전부 없앴습니다.

예전에는 +7 이면 무조건 치명타, +8 이면 무조건 흡혈이었습니다. 그래서 같은 검 두 자루가
언제나 똑같았고, 강화가 그저 "정해진 계단 오르기"였습니다. 지금은 **부위마다 다른 통에서
아무거나 뽑고, 수치도 그 자리에서 굴립니다.** 같은 룬 갑옷이라도 서로 다른 물건이 됩니다.

| 부위 | 뽑히는 옵션 |
|---|---|
| **무기** | 흡혈 5~8% · 공격력 5~10% · 방어도 5~10% · 생명력 5~10% · 치명타 1~5% · 치명타 피해 5~20% |
| **방어구** (갑옷·어깨·장갑·신발) | 방어도 5~10% · 생명력 5~10% · 피해 경감 5~10% · 힘 +5~10 · 민첩 +5~10 · 지능 +5~10 |
| **장신구** (반지·목걸이·허리띠) | 치명타 피해 10~25% · **흡혈 5~8% (허리띠만)** · 생명력 10~20% · 힘/민첩/지능 +5~10 · 치명타 6~10% |

- **방어구에는 치명타 확률도 치명타 피해도 붙지 않습니다.** 때리는 값은 무기와 장신구가,
  버티는 값은 방어구가 맡습니다 — 그래야 "무엇을 입을까"와 "무엇을 들까"가 다른 물음이 됩니다.
  표에 실수로 적어 넣어도 `AffixSystem` 이 걸러 내므로 조용히 새지 않습니다.
- 한 장비에 **같은 옵션이 두 번 붙지 않습니다.**
- 힘·민첩·지능 옵션은 특성 포인트를 그만큼 더 찍은 것과 같게 계산됩니다.
- 통과 수치 범위는 전부 `src/data/affixes.json` 한 파일에 있습니다. 규칙은 코드에,
  숫자는 표에 — 다른 표들과 같은 방식입니다.

### 보석 (+10 이후)

+10 이 되면 **홈이 하나** 열리고, 지하감옥에서 얻은 보석을 박을 수 있습니다.
한 번 박으면 빠지지 않으니 무엇을 넣을지가 선택이 됩니다.

| 보석 | 효과 | 보석 | 효과 |
|---|---|---|---|
| 루비 | 공격력 +8% | 토파즈 | 치명타 +5% |
| 사파이어 | 생명력 +10% | 자수정 | 치명타 피해 +18% |
| 에메랄드 | 피해 경감 +6% | 오닉스 | 흡혈 +7% (무기·허리띠 홈에만) |
| 다이아몬드 | 방어 관통 +10% | | |

보석은 **주로 지하감옥에서** 나옵니다(아래 참고).
강화는 마을 대장간에서, 보석 박기도 마을 대장간에서 합니다.

#### 동쪽 필드에서는 보석이 안 나옵니다 (0.49)

0.40 에서 1~5단계 잡몹에게 루비·에메랄드·오닉스를 각 2~3% 씩 뿌려 두었습니다.
초월 강화의 값이 그 셋이라 이른 단계에서도 조금씩 쌓이게 하려던 것이었는데,
**보석이 흔해지면 지하감옥에 갈 이유가 없어집니다.**

그래서 **1~20단계(동쪽 필드) 전체에서 보석 줄을 뺐습니다.** 잡몹도 보스도입니다.
남은 것은 딱 하나입니다:

| 몬스터 | 보석 | 확률 |
|---|---|---|
| 잿빛 늑대 | 사파이어 | **1%** |

이 한 줄은 **이벤트로 남긴 것**입니다 — 처음 손으로 넣으신 줄이고,
"어쩌다 하나 나오면 기분 좋은" 자리이기 때문입니다.

보석은 **지하감옥과 고룡에게서** 나옵니다. 그쪽 줄은 그대로입니다.
악마의 핵(영웅 장비 강화 재료)도 그대로라, 이른 단계에서 쌓이는 것은 그쪽입니다.

| 몬스터 | 악마의 핵 |
|---|---|
| 꼬마 악마 | 42% 3개 |
| 악마 정찰대장 (5단계 보스) | 100% 3~9개 |

이 값들은 전부 시트의 `drops` 탭에 있습니다.

#### 두 번째 홈 — 악마의 파편 (0.42 에서 이름을 바꿨습니다)

한 장비의 홈은 **최대 두 개**입니다. 둘째 홈은 강화로는 절대 열리지 않고,
**악마의 파편**으로만 만듭니다. 이름만 보고도 무엇에 쓰는지 알 수 있게
설명 첫 줄을 **"장비에 보석 홈을 하나 더 만든다"** 로 바꿨습니다 —
'송곳' 은 무엇에 쓰는 물건인지가 이름에도 설명에도 앞서 나오지 않았습니다.

| 항목 | 규칙 |
|---|---|
| 어디서 나오나 | **지하감옥에서만** — 망령 · 석상 · 감옥의 주인 |
| 확률 | **0.001%** (10만 번에 한 번). 목표로 삼고 캘 물건이 아닙니다 |
| 쓸 수 있는 곳 | **무기 · 반지 · 목걸이 · 허리띠**. 방어구에는 못 씁니다 |
| 조건 | **+10 이상**, 한 장비에 **한 번**뿐 |

방어구를 뺀 이유는 밸런스입니다. 여섯 칸 모두에 보석을 두 알씩 박을 수 있게 두면
한 벌을 갖춘 사람과 아닌 사람의 차이가 감당할 수 없이 벌어집니다.

> **밸런스 기준은 홈 하나입니다.** 송곳이 0.001% 라 "누구나 갖춘 몸"으로 볼 수 없기 때문입니다
> (`tools/balance.js` 가 `affixes.json` 의 `홈` 표를 읽어 그만큼만 채웁니다).
> 그래서 둘째 홈은 순수한 덤입니다 — 없어도 지하감옥 5층은 잡히도록 맞춰 두었습니다.

### 옵션 다시 굴리기 (리롤)

붙은 옵션이 마음에 안 들면 **그 자리 하나만** 대장간에서 다시 굴릴 수 있습니다.
옵션 줄 오른쪽의 **다시** 버튼입니다.

- **강화 단계는 그대로입니다.** 떨어지거나 부서지지 않으니 마음 편히 굴릴 수 있고, 대신 값이 비쌉니다.
- 나머지 자리에 이미 붙은 옵션은 통에서 빠지므로 **같은 것이 두 번 붙지 않습니다.**
- 방금 있던 그 옵션은 통에 남겨 둡니다 — 같은 옵션이 더 좋은 수치로 뜰 수도 있어야 하니까요.
- 값은 골드 + 그 장비 등급의 강화 재료 3개. 뒤쪽 자리일수록 비쌉니다(`formulas.js` 의 `REROLL_*`).

### 초월 강화 (+10 → +15) — 성 안 왕실 대장간 (0.40)

+10 에서 멈춘 장비는 **성 안 왕실 대장장이 도르한**이 더 올려 줍니다.
마을 대장장이 고르드의 망치는 +10 까지고, 그 너머는 이쪽 일입니다.

| 단계 | 성공 확률 |
|---|---|
| +10 → +11 | **90%** |
| +11 → +12 | 80% |
| +12 → +13 | 70% |
| +13 → +14 | 60% |
| +14 → +15 | **50%** |

**값은 보석 한 개입니다.** 부위마다 쓰는 보석이 다릅니다.

| 부위 | 보석 |
|---|---|
| 무기 | **루비** |
| 방어구 (투구·갑옷·어깨·장갑·신발) | **에메랄드** |
| 장신구 (반지·목걸이·허리띠) | **오닉스** |

- **실패해도 부서지지 않고, 내려가지도 않습니다.** 보석만 사라지고 그 자리에 그대로 있습니다.
- 다섯 단계를 다 올리는 데 드는 보석의 기댓값은 **8.2개**입니다
  (1/0.9 + 1/0.8 + … + 1/0.5). 운이 나빠도 **앞으로만 갑니다.**
- +15 에 닿으면 화면이 한 번 **번쩍**입니다. 그 물건은 거기가 끝입니다.

> **0.39 까지는 마녀가 용의 징표를 받고 걸어 주었고, 실패하면 한 단계 내려갔습니다.**
> 기댓값이 한 번에 +0.1 단계라 +15 까지 쉰 번쯤 걸어야 했고, 그 앞에 고룡을 몇 번씩
> 잡아 징표를 모으는 일이 또 있었습니다. 그래서 +10 에서 "여기가 끝인가" 하고 멈추는
> 일이 실제로 있었습니다. 지금은 보석으로 걸고, 내려가지 않고, 성 안에 사람이 서 있습니다 —
> 남은 것은 운이 아니라 시간입니다. 이미 +11 이상인 장비는 그대로 유지됩니다.

**강화 재료는 장비 등급이 정합니다** — 단계마다 바뀌지 않습니다.
"이 검을 +10까지 올리려면 무엇을 모아야 하나"에 한 줄로 답할 수 있어야 하기 때문입니다.

| 장비 등급 | 필요한 재료 |
|---|---|
| 일반 · 고급 | **약초**만 |
| 희귀 | **마력석**만 |
| 영웅 | **악마의 핵**만 |

개수만 강화 단계에 따라 늘어납니다(2단계마다 +1개, +1~+2는 1개 … +9~+10은 5개).
표는 `formulas.js` 의 `ENHANCE_MATERIAL_BY_RARITY` 와 `ENHANCE_MATERIAL_COUNT` 입니다.
성문에서 파는 **룬 방어구·장신구는 영웅(보라)** 등급이라 +10까지 **악마의 핵**을 씁니다.
같은 가게의 무기(서리검·뇌전궁·성염 지팡이)는 희귀(파랑)라 마력석을 씁니다 — 값이 다르니 헷갈리지 마세요.

**상점** — 구매 탭에서 뭉치로 쌓이는 물건(회복약·재료)은 **×1 / ×10 두 가지 버튼**으로 삽니다.
판매 탭은 줄 왼쪽의 네모나 이름을 눌러 **여러 개를 골라 한 번에** 팔 수 있고,
아래 띠에 고른 종류·개수·합계 금액이 뜹니다("전부 선택" 버튼도 있습니다).
뭉치 하나를 "1개만" 팔거나 "전부" 파는 버튼은 줄마다 그대로 남아 있습니다.

**여관** — 20골드로 HP를 모두 채우고 **5분간 초당 HP 5 재생 + 이동속도 1.5배** 버프를 받습니다.
상점의 **질주의 물약(50골드)** 은 90초간 이동속도 1.5배입니다.

**재료 교환** — 무기점 아래 연금술사 집의 세피가 잡동사니를 강화 재료로 바꿔 줍니다.

| 주는 것 | 받는 것 |
|---|---|
| 슬라임 젤리 ×8 | 마력석 ×1 |
| 박쥐 송곳니 ×6 | 마력석 ×1 |
| 약초 ×5 | 마력석 ×1 |

| **사냥꾼** | 반사 신경 | 피해를 입으면 **바로 다음 한 대는 무조건 회피** |

> **왜 "한 번은 반격한 뒤"인가 — 시간만으로 재면 아무 값도 못 했습니다.**
>
> 예전에는 보호막이 **0.5초 동안만** 무적이었습니다. 그런데 한 차례의 간격은 0.62초라,
> 무적은 다음 공격이 오기 전에 이미 풀려 있었습니다. 상대가 하나일 때는 마법사가 먼저
> 움직여서 그럭저럭 한 대를 돌려줬지만, **둘 이상이면 100판 모두 반격 한 번 못 하고 죽었습니다.**
> 마법사는 최대 넷을 끌고 오는 직업이므로, 정작 제 방식대로 싸울 때 패시브가 통째로 없는 셈이었습니다.
>
> 그래서 규칙을 "0.5초 동안"이 아니라 **"0.5초 동안, 그리고 내가 한 번 휘두를 때까지"** 로 바꿨습니다.
> 이제 넷에게 둘러싸여도 100판 모두 반격을 돌려줍니다. 그 한 대가 두 번 들어가므로
> "버티기만 하고 그대로 죽는" 일이 없습니다. 스킬 **보호막 연장**(랭크당 +0.3초)은
> 그 위에 시간을 더 얹습니다.
>
> 확인은 `node /tmp/shieldtest.js` — 한 마리·넷·빠른 상대 세 경우를 100판씩 돌려
> "터졌는가"가 아니라 **"터지고 나서 값을 했는가"** 를 잽니다.

캐릭터 창(`C`)의 장비 탭 맨 아래에 지금 직업의 패시브와 전투 방식이 적혀 있습니다.

용린 투구가 버티는 쪽이라면 이쪽은 마법 쪽이라, 투구 칸에 고를 것이 생깁니다.

**잡화상 마르타** — **성 밖 포이노 마을**. 처음 쓰는 물건들과, 0.36 부터 **용린 세 조각**
(투구 · 갑옷 · 어깨갑옷, 각 20,000골드)을 팝니다. 성문은 레벨 25에 열리는데 용린은
그보다 앞에 입는 물건이라, 성 안에 두면 정작 필요한 사람이 살 수가 없었습니다.

이 장비는 그냥 "다음 등급"이 아니라 **11~20단계를 통과하기 위한 기준선**으로 맞춰 두었습니다.
실제 전투식으로 돌려 확인한 결과는 이렇습니다(용사 기준, 희귀 회복약 지참).

| 상황 | +0 | +5 | +7 | +9 |
|---|---|---|---|---|
| 20단계 잡몹 | 이김(물약 많이) | 이김 | 이김 | 이김(물약 1개) |
| 15단계 보스 | 짐 | **이김** | 이김 | 이김 |
| 20단계 보스 | 짐 | 짐 | 짐 | **이김** |

즉 **무기를 +9까지 올려야 20단계 보스를 잡을 수 있습니다.** 의도한 벽입니다.

### 용린 세트 — 룬 장비 앞에 서는 징검다리, 그리고 고룡 사냥 (0.35 · 0.36)

룬 장비는 성 안 무기상에서 팝니다. 그런데 그 앞에는 아무것도 없어서, 10단계 보스를 넘은
사람이 룬 한 벌을 살 돈을 모을 때까지 **입을 것이 없는 구간**이 있었습니다.
그 자리를 메우는 것이 용린입니다. 0.36 에서 **네 조각**이 되었습니다.

| 자리 | 칸 | 등급 | 값 | 어디서 |
|---|---|---|---|---|
| 용린 투구 | **투구** | 희귀 | 20,000 | **성 밖 · 잡화상 마르타** |
| 용린 갑옷 | 갑옷 | 희귀 | 20,000 | **성 밖 · 잡화상 마르타** |
| 용린 어깨갑옷 | 어깨 | 희귀 | 20,000 | **성 밖 · 잡화상 마르타** / `무너진 초소까지` 퀘스트 보상 |
| **용린 기사검 / 기사궁 / 기사장** | 무기 | 희귀 | — | **만들어야 합니다** (아래) |

> **무기 자리는 하나입니다.** 검·활·지팡이 셋 중 **제 직업 것 하나**면 그 자리가 채워집니다.
> 그래서 다 갖추면 `4/4` 입니다 — 셋을 다 만들 필요가 없습니다.
> 표에서는 그 자리를 `[ ]` 로 묶어 적습니다(`affixes.json` 의 `부위`).

> 0.35 에서는 성 안 무기상이 팔았습니다. 0.36 부터 **성 밖 마을의 마르타**로 옮겼습니다 —
> 성문은 25레벨에 열리는데 용린은 그보다 앞에 입는 물건이라, 성 안에 두면
> 정작 필요한 사람이 살 수가 없었습니다.

| 모은 개수 | 화면에 뜨는 글 | 실제로 하는 일 |
|---|---|---|
| **2개** | 공격력 +15% | 그대로 |
| **3개** | 받는 마법 피해 -50% | 그대로 |
| **4개** | **용에게 특별한 힘이 발휘한다** | 카르나크 — 힘·민첩·지능 **+100**, 주는 피해 **2배**<br>아그라모스 — **+100 뒤 다시 +200%**, 주는 피해 **2배** |

> **4세트는 창에 한 줄만 뜹니다 (0.49).** 안에는 상대별로 두 줄이 들어 있지만,
> 둘 다 '4개' 자리라 나란히 적으면 **두 벌을 맞춰야 하는 것처럼** 보입니다.
> 그래서 둘째 줄은 `글` 을 비워 두고, 창은 글이 빈 줄을 안 적습니다.
> 무엇이 얼마나 붙는지는 숫자로 보여 주지 않습니다 — 용 앞에 서 봐야 아는 편이 낫습니다.

> **왜 아그라모스만 배율까지 주나** — 200% 만 걸면 오히려 약해집니다.
> 만렙의 지능이 16 쯤이라 세 배를 해도 48 인데, 카르나크 줄이 주는 +100 은 116 입니다.
> "더 세게" 라고 해 놓고 더 약해지는 셈이라, +100 을 먼저 얹고 그 위에 200% 를 겁니다.
> 그래서 용린 한 벌을 갖추면 아그라모스는 **한두 판에 눕습니다**(예전에는 2~5판).

- 세트 효과는 **강화 수치를 타지 않습니다.** +15 로 올려도 그대로입니다.
  강화가 곱해지면 세트 하나가 다른 모든 선택을 지워 버립니다.
- **4세트는 평소에는 꺼져 있습니다.** 고룡 앞에 섰을 때만 켜집니다 —
  그래서 사냥 효율에는 아무 영향이 없고, 이 한 벌은 오직 고룡을 잡으러 가는 장비입니다.
  화면에서도 ◆(지금 켜짐) 가 아니라 **◈**(개수는 채웠고 그때가 되면 켜짐) 로 뜹니다.
- 어느 상대에게 켜지는지는 표에 적혀 있습니다(`affixes.json` 의 `상대`).
  **두 번째 고룡을 넣을 때는 그 줄에 id 하나를 더하면 됩니다** — 코드는 안 고칩니다.

#### 용린 기사무기 — 쓸모없는 검을 깨우기

성 안 무기상이 **쓸모없는 검**을 10만 골드에 팝니다. 공격력이 **1** 입니다.
값은 검이 아니라 그 검에 뚫려 있는 **홈 두 개**에 치르는 것입니다.

> **고룡을 한 번이라도 만나 봤다면 그 10만 골드는 돌려받습니다.**
> `쓸모를 잃은 무기` 라는 **특별 의뢰**가 열려서, 그 검을 가져오면 10만 골드를 줍니다.
> 아래 '특별 의뢰' 를 보세요.

```
쓸모없는 검 (공격력 1 · 홈 2)  +  루비 → 에메랄드  =  용린 기사검 / 기사궁 / 기사장
```

**무엇이 되는지는 그때 손에 쥔 사람의 직업이 정합니다.**

| 직업 | 되는 것 | 능력치 |
|---|---|---|
| 용사 | 용린 기사검 | 공격 56 · 방어 8 · 생명 120 · 치명 6% |
| 사냥꾼 | 용린 기사궁 | 공격 52 · 방어 6 · 생명 100 · 속도 8 · 치명 10% |
| 마법사 | 용린 기사장 | 공격 54 · 방어 8 · 생명 130 · 치명타 피해 14% |

- **순서가 있습니다.** 루비를 먼저, 에메랄드를 나중에 박습니다.
- **차례가 아닌 보석은 아예 박히지 않습니다.** 보석은 한 번 박으면 빠지지 않으므로,
  그냥 박히게 두면 10만 골드짜리 검이 되돌릴 수 없이 못 쓰게 됩니다.
  규칙은 지키되 그 규칙 때문에 사람이 물건을 잃지는 않게 했습니다 —
  무엇을 박을 차례인지 알려 주고 막습니다.
- 자세히 보기에 **`변신 · 1/2 → 용린 기사검`** 과 함께 다음 차례가 ▶ 로 뜹니다.
- 다 박으면 그 자리에서 이름이 바뀌고, **박은 보석 둘은 그대로 남습니다**(루비 +8% · 에메랄드 +6%).
- 홈은 강화와 상관없이 태어날 때부터 있습니다(`affixes.json` 의 `변신` 표가 정합니다).

이 무기들의 공격력(52~56)은 서리검(82)·뇌전궁(76)·성염 지팡이(78)보다 낮습니다.
**일부러 그렇습니다.** 평소 사냥에는 그쪽이 낫고, 고룡 앞에서만 이 한 벌이 다른 물건이 됩니다.

### 촌장에게 한 번 더 말 걸기 (0.38)

NPC 에게 **연달아 한 번 더** 말을 걸면 다른 이야기를 합니다(`npcs.json` 의 `lines2`).
사이에 다른 사람과 말하면 처음으로 돌아갑니다.

촌장 하렌에게 두 번 말을 걸면 용린 기사검 이야기를 흘립니다 —
"아무도 안 사는 이 빠진 쇳덩이였는데", "붉은 돌 하나, 푸른 돌 하나".
**순서는 일러 주지 않습니다**("그건 나도 잊었네"). 그 자리는 사람이 채우는 자리입니다.

> 게임에 필요한 실마리를 첫 마디에 다 얹으면 대사가 안내문이 됩니다.
> 한 번 더 말을 거는 것은 사람이 스스로 하는 일이라, 거기서 나온 이야기는
> "내가 캐낸 것"이 됩니다.

### 특별 의뢰 — 게시판 차례와 상관없이 열리는 줄 (0.37)

게시판의 의뢰는 위에서 아래로 한 줄씩 이어집니다. 그런데 "고룡을 본 사람에게만"
처럼 **순서와 상관없이** 열려야 하는 것이 있습니다. 그런 줄은 차례에서 빠지고,
조건이 채워지면 퀘스트 창의 **특별 의뢰** 칸에 따로 뜹니다(금빛 머리글).

| 의뢰 | 열리는 조건 | 하는 일 | 보상 |
|---|---|---|---|
| 쓸모를 잃은 무기 | **고룡을 한 번이라도 만나면** | 쓸모없는 검을 가져온다 | 🪙 100,000 |

- 조건은 표에 적습니다 — `quests` 탭의 **`열림조건`** 칸에 `met:great_dragon`.
  비어 있으면 여느 때처럼 차례대로 이어지는 줄입니다.
- **잡았을 때가 아니라 붙었을 때** 열립니다. 고룡은 한 번에 눕는 상대가 아니라,
  잡아야만 열리게 두면 정작 그 의뢰가 필요한 사람에게 영영 안 열립니다.
- 특별 의뢰를 끝내도 **게시판 차례는 밀리지 않습니다.** 밀면 게시판의 다음 의뢰
  하나가 통째로 건너뛰어집니다.
- 새 조건을 늘리려면 `systems/QuestSystem.js` 의 `isUnlocked` 에 한 줄 더하면 됩니다.

**세트 아이템은 초록색으로 보입니다.** 소지품 목록에서도, 자세히 보기의 이름에서도

## 직업 추가하기

`src/data/classes.json` 에 항목을 하나 더 넣으면 접속 화면의 직업 선택에 나타납니다.

```jsonc
"mage": {
  "name": "마법사",
  "tagline": "한 방으로 끝낸다",
  "available": true,                 // false 면 '준비 중'으로 회색 표시
  "sprite": "chr_mage_field",        // manifest.json 에 등록한 키
  "battleSprite": "chr_mage_battle",
  "baseStats": { "hp": 34, "atk": 16, "def": 3, "spd": 10, "crit": 0.08 },
  "growth":    { "hp": 3.5, "atk": 3, "def": 0.8, "spd": 0.9, "crit": 0.005 },
  "startItems": [{ "id": "potion", "count": 3 }],
  "skills": ["power_strike", "keen_edge"]   // 이 직업이 배울 수 있는 스킬만

```

기본 스탯·성장·시작 장비·배울 수 있는 스킬이 전부 데이터에 있으므로 JS 수정은 없습니다.

스프라이트는 두 가지 방법이 있습니다.

1. **그려서 만들기** — `tools/art-class.js` 에서 `heroSvg({ hair, headgear, behind })` 를 한 번 더 부르고

2. **원본 일러스트 쓰기** — `tools/prep-hero.py` 로 구운 뒤 `manifest.json` 에 키를 등록합니다.

## 설계 한 줄 요약

```
입력 ─→ 시스템(순수 로직) ─→ EventBus ─→ 씬(캔버스) / UI(HTML)
                 ↑
            data/*.json  (숫자와 경로만)
```

핵심 규칙 5가지:

1. `systems/` 는 서로를 import 하지 않는다. 통신은 **EventBus**로만.
2. `systems/` 와 `entities/` 는 `document` / `canvas` 를 절대 만지지 않는다.
3. `ui/` 는 상태를 읽기만 하고, 조작은 이벤트로 발행한다 (`ui:equip`, `ui:buy`, `ui:enhance` …).
4. `data/*.json` 에는 로직이 없다. 숫자·문자열·에셋 경로만.
5. 밸런스 상수는 `data/formulas.js` 와 `config.js` 밖으로 나가지 않는다.

새 시스템을 추가할 때 고칠 파일은 원칙적으로 `src/main.js` 하나뿐입니다.

## 전투가 동작하는 방식

턴제 조작이 없습니다. 접촉 순간의 스탯만으로 **전투 전체가 즉시 계산**되고, 화면은 결과를 재생만 합니다.

```
EncounterSystem     "부딪혔다"           → emit('battle:request')
        ↓
CombatSystem        스탯 스냅샷 → 타임라인 배열 (순수 함수, 같은 seed → 같은 결과)
        ↓
BattleScene         타임라인을 t(ms) 기준으로 재생 (캔버스: 흔들림·플래시)
        ↓
BattleView          같은 이벤트로 HP바·데미지 숫자·로그 표시 (HTML)
        ↓
main.js             연출이 끝나면 보상/경험치/드랍을 실제 상태에 반영
```

```js
{ t: 1200, type: 'hit', actor: 'player', target: 'monster',
  damage: 39, crit: true, targetHpAfter: 0, targetMaxHp: 34 }
```

**턴제나 스킬을 넣으려면 `CombatSystem.js`만**, **연출을 바꾸려면 `BattleScene.js` / `BattleView.js`만** 고치면 됩니다.

### 한 대의 피해가 정해지는 순서

`CombatSystem.js` 의 `strike()` 가 **이 차례대로** 곱해 나갑니다. 더하는 자리는 없습니다.

```
① 기본       damage(공격력 × 분노배율,  방어력 × (1 − 방어관통),  흔들림,  치명타)
                 = 공격력 × 공격력/(공격력 + 방어력×0.55)     ← 방어력이 깎는 몫
                   × (1 ± 12% 흔들림)
                   × (치명타면 1.5 + 치명타피해)
② 위력       × 스킬·연출 배율 (광역 여파 0.7, 마법사 대폭발 1.4, 반격 1.2 …)
③ 마법       ★ 때리는 쪽이 마법일 때만 ★
                 × (1 + 내 마법 피해)
                 × (1 − 상대 마법 저항)          ← 최대 80%까지만
④ 위기       × (1 + 위기의 피해 증가)            ← HP 가 임계 아래일 때만
⑤ 감경       × (1 − 상대의 받는 피해 감소)
⑥ 1:1        × (1 − 마법사 단독 대치 감소 25%)   ← 상대가 한 마리뿐일 때만
```

**"(총 공격력에 의한 피해 + 추가 마법 피해) × 스킬 마법 피해" 가 아닙니다.**
따로 더해지는 "추가 마법 피해" 라는 값은 **어디에도 없습니다.**
마법은 ①②로 이미 다 계산된 숫자에 **곱하는 배수 하나**일 뿐입니다.

그리고 마법 피해를 올려 주는 것들은 **서로 곱하지 않고 먼저 다 더한 뒤, 한 번만 곱합니다.**

| 어디서 | 얼마나 | 지능 100 · 마력 증폭 3 · 특성 5점이면 |
|---|---|---|
| 지능 | 1점당 **+1%** | +100% |
| 스킬 **마력 증폭** | 랭크당 **+6%** (최대 3랭크) | +18% |
| 특성 **마법 피해 증가** | 1점당 **+15%** (최대 5점) | +75% |
| | **합** | **+193% → ×2.93** |

> 아이템의 `마법` 칸(서리·뇌전·성염·보호…)은 **이름표일 뿐 피해와 무관합니다.**
> 룬 장비를 알아보기 쉬우라고 붙인 글자입니다.

**누가 마법으로 때리나** — `classes.json` 의 `combat.school` 이 `magic` 인 직업뿐입니다.
지금은 **마법사만** 그렇습니다. 용사·사냥꾼은 지능을 아무리 올려도 ③이 통째로 건너뛰어집니다
(지능의 `마법 저항`은 **맞을 때** 쓰이므로 세 직업 모두에게 듣습니다).

실제로 그렇게 도는지는 `node /tmp/magictest.js` 가 매번 확인합니다 —
같은 씨앗으로 속성만 바꿔 때려 보고 ×1.3 · ×0.75 가 정확히 나오는지 잽니다.

## 콘텐츠 추가하는 법 (JS 수정 0줄)

### 새 몬스터
`src/data/monsters.json` 에 추가 → 필드 정의의 `monsters` 배열에 id를 넣으면 등장합니다.
`"boss": true` 를 붙이면 보스 취급(큰 체구, 느린 리스폰, BOSS 표시)이 됩니다.

### 드랍표 — `src/data/drops.json`
몬스터가 뭘 떨구는지는 **표 하나에 모여 있습니다.** 한 줄이 드랍 하나입니다.

```jsonc
"표": {
  "slime": [
    // [ 아이템id,       확률,  최소, 최대 ]
    ["slime_jelly",      0.75,  1,    2],
    ["herb",             0.25,  1,    1],
    ["club",             0.03,  1,    1]
  ]
}
```

확률은 0~1(0.75 = 75%)이고, 표의 줄마다 따로 굴리므로 여러 개가 동시에 나올 수 있습니다.
표에 없는 몬스터는 아무것도 떨구지 않습니다.

```bash
node tools/print-tables.js drops   # 표를 보기 좋게 출력 + 오타 검사
```

### 퀘스트표 — `src/data/quests.json`
게시판 의뢰도 **표 한 장**입니다. 위에서 아래로 순서대로 이어집니다.

```jsonc
"표": [
  // [ id,     제목,          조건,      대상,          개수, EXP,  골드, 보상템,          수량, 설명, 필요레벨, [선택보상] ]
  ["jelly5",   "말랑한 증거", "collect", "slime_jelly", 5,    200,  500,  "",              0,   "젤리 5개를 모아 오게."],
  ["hunt_wolf","골짜기의 울음","hunt",   "wolf",        8,    900,  1200, "leather_armor", 1,   "늑대 8마리를 정리해 주게."],
  ["class15",  "직업 시험",   "hunt",    "imp_captain", 1,    5000, 6000, "",              0,   "정찰대장을 쓰러뜨리고 오게.",
                                                                              15, ["flame_sword", "knight_armor"]]
]
```

- **조건** — `collect`(아이템 모으기, 완료 시 회수) · `hunt`(몬스터 처치) · `reach`(단계 도달)
- 보상 아이템이 없으면 `""` 와 `0`
- **필요레벨**(11번째 칸) — 넣으면 그 레벨이 되어야 보상을 받을 수 있습니다. 없으면 제한 없음.
- **선택보상**(12번째 칸) — `["itemA","itemB"]` 를 넣으면 완료할 때 **둘 중 하나를 골라** 받습니다.
  기본으로 들어 있는 **15레벨 직업 퀘스트**가 이 방식입니다: 5단계 보스(악마 정찰대장)를 잡고
  **화염검(레어 무기) 또는 기사 갑옷(레어 방어구)** 중 하나를 고릅니다.
- 마지막 두 칸은 없어도 됩니다 — 예전 줄은 그대로 동작합니다.
- 줄 하나만 추가하면 새 의뢰가 붙습니다. JS 수정은 없습니다.

```bash
node tools/print-tables.js quests  # 표 출력 + 없는 아이템/몬스터 검사
```

게시판은 마을 **동쪽 출구 앞(35,14)** 에 서 있고, 클릭하면 현재 의뢰·진행도·보상과
지나온 의뢰 목록이 보입니다. HUD에도 진행 중인 의뢰가 한 줄로 따라다닙니다.

#### 창은 두 칸입니다 — 왼쪽 진행 중, 오른쪽 목록 (0.49 에서 고침)

왼쪽 칸에 **진행 중 의뢰 + 특별 의뢰**가 한 덩어리로 들어가고, 오른쪽 220px 이

> ⚠ 왼쪽 둘은 반드시 `.quest-left` 하나로 **묶어 둡니다.**
> 예전에는 셋(진행 중·특별·목록)이 두 칸짜리 격자에 그냥 들어 있었습니다.
> 격자는 셋째를 다음 줄로 넘기므로, 의뢰 목록이 오른쪽이 아니라

#### 퀘스트 보상은 상점에서 산 것과 똑같이 태어납니다 (0.49)

예전에는 **퀘스트 보상만 각인을 안 굴렸습니다.** 드랍과 상점 구매는 `engraveNew()`
를 지나는데 퀘스트 완료만 `Inventory.addItem()` 을 곧장 불렀기 때문입니다.
그래서 같은 **용린 어깨갑옷**인데 상점 것에는 ✦ 각인이 붙고 퀘스트로 받은 것에는
안 붙어, 같은 이름의 다른 물건처럼 보였습니다.

**장비가 소지품에 들어오는 길은 하나로 둡니다** — `engraveNew(Inventory.addItem(...))`.

  를 넣으면 시드 기반으로 지형이 만들어집니다. 같은 seed면 항상 같은 지형입니다.

### 포탈 (맵 이동 · 입장 제한)
어떤 맵이든 `portals` 배열로 연결합니다.

```jsonc
{ "x": 19, "y": 7, "to": "castle", "toX": 11, "toY": 13,
  "requireLevel": 25, "blockedText": "성문 위병: 레벨 25에 이르지 못한 자는 통과할 수 없다." }
```

`requireLevel` 미달이면 이동이 막히고 위병 대사창이 뜹니다.

**구간 자물쇠** — 보스가 있는 단계의 동쪽 문에는 두 칸이 더 붙습니다.

```jsonc
{ "x": 39, "y": 15, "to": "field_6", "toX": 1, "toY": 15,
  "requireBossOf": "field_5",        // 이 맵의 보스를 잡았는가(웨이포인트 해금으로 판정)
  "requireQuestOf": "imp_captain" }  // 그 보스를 잡는 퀘스트를 완료했는가
```

둘 다 채워야 다음 구간으로 넘어갑니다. 잡기만 하고 마을에 보고하지 않았다면 아직 닫혀 있습니다.
판정은 `PortalSystem` 이 하지 않고 `main.js` 의 `portalGate` 가 합니다 —
"보스를 잡았는가"는 웨이포인트가, "퀘스트를 마쳤는가"는 퀘스트가 알고 있고,
system 끼리는 서로 import 하지 않기로 했기 때문입니다.

## 이미지 교체

`assets/` 안의 PNG를 같은 이름으로 덮어쓰면 끝입니다. 파일이 없으면 이름이 적힌 색 박스로
대체되므로, 그림이 아직 없어도 게임은 정상 동작합니다.

| 용도 | 그릴 크기 | 경로 |
|---|---|---|
| 필드 캐릭터 | 48×64 | `assets/sprites/characters/{id}_field.png` |
| NPC | 48×64 | `assets/sprites/npc/{id}.png` |
| 필드 몬스터 | 48×48 | `assets/sprites/monsters/{id}_field.png` |
| 전투 몬스터 | 256×256 | `assets/sprites/monsters/{id}_battle.png` |
| 타일 | 32×32 | `assets/tiles/{name}.png` |
| 아이템 아이콘 | 64×64 | `assets/ui/items/{id}.png` |

- 전부 **투명 배경 PNG**, 발밑이 이미지 하단에 닿도록 정렬.
- `manifest.json` 의 `w`/`h` 는 **화면에 그릴 크기**입니다. 실제 파일은 2배(레티나) 해상도로
  넣어도 같은 크기로 선명하게 그려집니다.
- 애니메이션이 필요해지면 manifest 항목에 `"frames": 4, "frameWidth": 96` 을 추가하면
  `AssetLoader` 가 자동으로 스프라이트시트로 인식합니다.

동봉된 기본 아트는 `tools/gen-assets.js` + `tools/art-town.js` 가 SVG로 그려 구운 것입니다.

### 캐릭터 스프라이트 생성 프롬프트 템플릿

```
A single {캐릭터 설명: 예 "young hero knight with brown hair, blue tunic, red cape"},
full body, front-facing three-quarter view, standing idle pose, feet flat at the very
bottom edge of the frame.

Style: clean 2D game sprite, soft cel shading with a subtle rim light from above,
rounded chibi proportions (head roughly 1/3 of body height), thick readable silhouette,
saturated but not neon colors, no outline noise.

Framing: centered, full body fits inside frame with ~6% margin.

Background: fully transparent. No ground, no shadow, no floor plane, no text, no border,
no watermark, no extra characters.

Output: PNG with alpha, {48x64 또는 192x256} pixels (or larger with the same 3:4 ratio).
```

### 몬스터 스프라이트 생성 프롬프트 템플릿

```
A single {몬스터 설명: 예 "round blue slime with glossy surface and cheerful eyes"},
front-facing, idle pose, creature sits at the bottom edge of the frame.

Style: clean 2D game sprite matching a friendly JRPG bestiary — soft cel shading,
one glossy highlight, bold simple silhouette readable at 48px, saturated palette
consistent with {같은 세트의 다른 몬스터 색감}.

Framing: centered, creature fills ~85% of the square frame.

Background: fully transparent. No ground shadow, no floor, no text, no border,
no watermark, no other creatures.

Output: PNG with alpha, square, {48x48 필드용 / 256x256 전투용} pixels.
```

> 세트의 일관성이 가장 중요합니다. 여러 마리를 뽑을 때는 **Style 문단을 한 글자도 바꾸지 말고**
> `{몬스터 설명}` 만 교체하세요.
